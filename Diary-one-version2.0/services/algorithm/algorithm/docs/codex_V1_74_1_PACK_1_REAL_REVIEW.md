## 4. Aha 为什么是 0

S09 实际收到全部 35 条事实，输入为 15,633 bytes。模型列出 8 个 finalists，并选择：

- 河边载红花的小船；
- 木架上的祈福签；
- 穿蓝色背心奔跑的小狗。

但同一回复又把它们分别判定为 Chapter 2、Chapter 2、Chapter 3 的 `SAME_STORY`。程序因此逐项关闭，最终 0 Aha。这个确定性拒绝符合已冻结原则：不能把“模型说选中”凌驾于同一回复里的重复关系，也不能从落选项自动补位。

模型还只返回了 3 条可能重叠的 Chapter/Aha 关系，没有返回 12 条完整关系。程序把缺失关系记为 `UNRESOLVED`；不过即使忽略这些缺失，每个候选已有一条明确的 `SAME_STORY`，所以它们仍应被拒绝。**缺失关系不是本轮 0 Aha 的主因，不能用“缺失即独立”来修。**

## 5. 真正的漏选

事实 `F026` 没有进入任何 Chapter，内容是：白色帐篷摊位、可见烤饼招牌、摊主正在设备前操作，前方同时陈列甜筒与包装食品。代表帧也清楚展示了这一现场。

它具备本轮所需的通用体验结构：一个完整、正在发生、可单独回看的现场，而且不依赖把店名本身当成价值。S09 看到了它，却没有放进 8 个 finalists；相反，仍把两个牌坊名称作为 `WORTH_REVISITING`，说明“完整事实已经传入”并不足以让模型可靠完成覆盖检查。

根因不是缺少烤饼或摊位特例，而是当前输入没有直接告诉模型每条事实是否已经被某个 Chapter 使用。模型需要自己在 35 条事实与 4 个 Chapter 列表之间做交叉比对，未被 Chapter 覆盖的事实因此没有得到单独审查。

这些问题记录但不与 Aha 主因混为一谈。
