# Diary One Algorithm V1.73｜Aha 集合编辑器检查点

日期：2026-09-15。状态：**本地实现与完整回归通过；等待冻结候选和素材包 1 全新真实链验证。**

## 1. 本步在全链中的位置

V1.73 只拆开此前挤在 S07 里的 Aha“发现”和“最终成组选取”：

```text
S04 视觉事实
  → S07 Chapter 方案 + 最多 8 个原子 Aha 候选
  → S09-A 一次纯文字 Aha 集合编辑
  → S09-B 程序引用/关系/数量校验与执行
  → S10 媒体精选
  → S11 单次 Writer
  → S12 发布前校验
```

Chapter 聚类、S04 事实识别、S10 媒体精选和 V1.72.1 Writer 规则没有在本步重新设计。V1.73 仍是独立研究入口，不是 Web/App 当前默认，更不是 Production 已就绪。

## 2. 已确认的产品边界

- 所有记录统一允许 `0–3` 个 Aha；有充分成立候选时主动争取 `2–3` 个。
- 只有 1 个成立时可以发布 1 个；0 个只代表没有可成立候选或 Aha 技术路径失败，不能从素材少、没有 Chapter 或普通生活直接推断为 0。
- 同一主题的多个 Aha 可以共存，但必须带来不同的回看体验；对象、店名、地点、角度或措辞不同本身不证明故事不同。
- 不为了达到目标数自动补位，也不重复调用 API 抽卡。

例子：一批素材不足以组成三件素材的 Chapter，但其中有三个彼此独立、各自事实充分的小瞬间，V1.73 允许保留三个 Aha；旧版“无 Chapter 最多一个”不再适用。

## 3. S07 发现合同

S07 继续生成和推荐 Chapter，同时只提出最多 8 个 Aha 候选，不再决定最终 Aha 选单或关系矩阵。每个候选仍必须是：

- 一个 observation；
- 一条已有支持事实；
- 该事实中的一个焦点帧；
- 一个不增加事实的 `moment_focus`。

程序仍会核对 observation、fact 和 focus frame 的归属。S07 候选重复、引用不明或不满足原子合同时，只拒绝对应候选，不由程序猜测或改写。

例子：S07 返回 6 个有效候选并不等于最后必须有 3 张卡；这 6 个只是交给 S09 比较的短名单。

## 4. S09-A 一次纯文字集合编辑

新增一次 Qwen3.7 Plus 文字调用。输入使用本次请求内的 `C01`、`A01`、`F001` 等短编号，只包括：

- 技术上可发布 Chapter 的内部主旨与已验证事实；
- 每个 Aha 候选的一条事实、证据强度、`moment_focus`、编辑职责和证据限制；
- 本批记录背景及明确的不确定性；
- 0–3 个 Aha 的数量合同。

不输入原图、原视频、GPS、导入顺序故事、motif、事件类别、对象稀有度、画质分或用户未提供的个人兴趣结论。模型需要逐个给出：

- `STANDALONE`：可以单独回看；
- `CHAPTER_SUPPORT`：更适合作为 Chapter 的组成；
- `UNRESOLVED`：现有文字事实不足以判断。

随后只从 `STANDALONE` 中选择最终集合，并为全部已选 Chapter/Aha 和 Aha/Aha 对返回事实绑定关系。

例子：两个候选都属于同一主题仍可同时保留，但编辑器必须说明第二个新增了什么不同的回看体验；只写“对象名称不同”不够。

## 5. S09-B 程序只做客观校验

程序检查短编号是否存在、review 是否完整、被选项是否为 `STANDALONE`、数量是否不超过 3、逐对关系是否唯一且引用输入中的事实。它不判断哪个场景更精彩，不读取标签打分，也不理解对象名称。

- 某个被选 Aha 的 review、事实或关系无效：只关闭该 Aha，有效兄弟项继续。
- Aha/Aha 为 `SAME_STORY`：保留编辑器排序更靠前者，关闭后者，不从落选项补一张。
- Aha/Aha 或 Chapter/Aha 为 `UNRESOLVED`：不把不确定当作独立证据。
- S09-A 调用失败：Chapter 继续，Aha 路径记录 `AHA_SET_EDITOR_UNAVAILABLE`，不回退旧选单、不重试。

例子：编辑器原本选择 A01、A02、A03，但 A01/A02 的唯一关系是 `SAME_STORY`，最终可以是 A01、A03；程序不会再拿 A04 补回三张。

## 6. Writer 与 24 字出口

V1.73 沿用 V1.72.1 的 Writer 合同：

- S11 只调用一次 Plus，不做 API 重写；
- Aha 正文以 20 个可见字符为目标，24 个为硬发布上限；
- 一条事实、一个焦点帧、一个中心动作/状态/发现；
- Aha 不能通过确定性长事实兜底绕过出口；
- Chapter 的既有单次模型与安全事实兜底保持不变。

新增 S09 不改写 Aha 文案，也不把 review 理由当成事实交给 Writer。

## 7. 成本、效率与失败范围

- 正常有候选时新增 1 次纯文字 Plus 调用；没有有效候选时跳过。
- 设计估算单次约 ¥0.016–¥0.032，必须以真实运行的 Token 和账单口径复核。
- 不重复 S04 视觉识别，不上传额外图片，不增加 Writer 调用。
- 失败只影响 Aha 选单，不能把已成立的 Chapter 一起清空。
