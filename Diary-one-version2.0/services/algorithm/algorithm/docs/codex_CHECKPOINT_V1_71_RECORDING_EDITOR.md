## 1. 授权、基线与本步范围

用户已认可D2设计，补充活动触发、分段佩戴的产品判断，并要求不等待功能样机、先做算法优化。本步在算法仓库实现独立研究入口：S04既有事实 → 可用Aha比较范围 → S07记录背景与Chapter/Aha共同推荐 → S09执行明确选单。S10、Writer继续原路径，后续分别优化。

进入实施前核验：V1.70清单SHA-256为`282299e31ccd59abd3a3e208dc1be1d6f9cefdebd616b46d1df68c6d085e3ef9`；46个活动/封存源码与合同一致。D2设计及其阅读索引的两项摘要一致。旧设计和真实运行记录不回写。

仅修改算法源码、独立本地测试、算法文档及新研究检查点。不改Web/App默认入口、Firmware/SDK、R2、共享状态、长期记忆、原素材；不公开同步私有事实。

## 2. 落地原则及例子

- 有KEEP角色、STRONG/MODERATE事实的素材可被考虑，不再要求事件类别或显著性等级。必须由模型提出有据Aha，不能用事件标签自动补位。例：真实包3的49号合影可参与，但不强制推荐。
- S07在原调用中给出简短的本批记录背景、尚不确定的信息，以及明确推荐的Chapter键/Aha观察编号。列表可为候选的子集，不再要求所有备选完整排序。例：真实包2两件用餐组不推荐为Chapter，不影响其他有效章。
- 背景是编辑判断，不是事实、兴趣分或普通/特别的硬分类。当前无可信时间、GPS、完整佩戴信息；不从素材少推断低价值，也不从一次导入推断完整一天。没有新时间门槛或场景模板。
- S09不再补满空位或调用旧价值排名，只执行推荐并检查来源编号、三件底线、容量、Chapter间精确素材重叠、Aha间精确重复和明确的Chapter/Aha同故事关系。同地点或标签相似不独立构成新路径的硬拦截。
- 例：真实包3的三个园区Aha若都出现，必须来自模型的明确共同推荐；这只能证明执行一致，不证明三张都有独立价值。

## 3. 缺损选单的确定性处理

- 合法空名单＝模型主动不推荐；缺少名单/类型错误＝技术缺损。两者在审计中分开，不把后者解释为素材无价值。
- 未知编号、歧义提案、失效候选只影响对应项；其他有效推荐可继续，但整组选单标为部分执行。重复编号只执行一次并记录异常。
- 缺少一路名单不改用旧排名，也不从未推荐候选补位。缺少背景/理由只作诊断，不连带删除有据有效卡片。不加模型重试。
- 冲突或容量让推荐无法完全执行时保留差异，不能标成完整执行或质量通过。

## 4. 明确保留、后续再改

本步继承研究容量4 Chapter / 3 Aha、无Chapter最多1 Aha、每章至少3件。普通日多个Aha及第5章例外仍是后续需统一的产品边界，不暗改。背景判断不改变这些数量。

当前研究函数本就不要求1.5–2小时才能运行；本步证明小素材集合可参与，不声称已修复正式App的增量触发。Sync、佩戴段结束识别、GPS接线另做。无样机不阻塞本步。

S10视频仅首帧、大于12件退回质量排序、计划与最终重点交接、Writer语言问题仍未修复。新入口不自动切到Web，不将研究能力冒称用户测试页已启用。

## 5. 验证要求

用既有三包真实观察/事实做离线接口回放，检查范围放宽、显式推荐、不补位、三件底线、同故事关系和短引用编解码。仅修改协议名单以检查接线，不构造新的画面语义错误，不作为正确名单标签。

单/少素材检查只能称“真实素材子集的接口检查”，不能称真实短时佩戴日。旧路径回归与新入口的实际请求检查必须通过。正式质量验收仍需同版重新标准化并跑S04–S12，逐包反馈；不以旧模型回复回放代替新质量测试。
