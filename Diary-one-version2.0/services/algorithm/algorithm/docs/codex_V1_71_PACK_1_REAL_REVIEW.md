## 3. 已证实的共性缺口

### 3.1 共同选单没有真正形成关系闭环

S07 推荐了 3 个 Chapter 和 3 个 Aha，却为三个 Chapter 的 `aha_relations` 全部返回空数组。最终审计中的 9 个 Chapter/Aha 关系因此全是 `UNRESOLVED / RELATION_MISSING`，程序仍然发布全部 Aha。模型的总理由写着“互补、无重复”，但没有逐对事实承担这个结论。

这是接口和执行缺口，不是模型偶发措辞问题：最终选中的每个 Aha 必须与已选 Chapter、其他已选 Aha 完成同故事/不同故事的逐对分工；缺少关系不能继续冒充完整共同推荐。

### 3.2 Aha 的最小语义单位仍然太大

A3 的一个事实把四帧中的狗奔跑、回望、路过电瓶车、茶店入口合在同一条 fact。后续虽然限制 Writer 只能使用这个 fact，仍等于一次交给 Writer 多个场景。Aha 应锁定一个受证据支持的 Moment 片段，而不是默认使用整条视频观察。

通用修正方向不是限制某类 object，而是：Aha 提名必须绑定一个原子事实/窗口；同一事实不能横跨多个可分离事件。Writer 只接收该 Moment 的主动作或发现，加最多一个环境支撑。

### 3.3 Writer 的“软提示”没有约束输出

请求已明确写出 Aha 20 字目标、21–24 字可接受并要求输出前计数，但本轮三条分别为 49、45、50 字。当前程序将它们标为“偏长待评价”后仍给出 `READY_PRIMARY_COPY / MODEL_SURFACE_VERIFIED`，状态表达不真实。

下一步应在同一次结构化输出中使用可机器执行的长度合同（Aha `text.maxLength = 24`）并实测供应商是否执行；不重复调用 API 抽卡。若供应商仍违反，结果只能进入 review 状态，不能标为主文案已就绪。

### 3.4 低置信文字和关系动词会把事实误差放大到文案

牌匾/碑文专名及“停泊→而行”“行走→疾行”均说明 Writer 的 claim-id 合法不等于每个词都被事实支持。通用处理应是：不确定 OCR 降级为“牌匾/石碑”，动作强度不得高于事实，不能用跨素材连接动词编造连续经历。

## 6. 建议的下一小步

不要直接把 V1.71 跑到包 2。先做一个仅修“选单完整性＋Aha 输出合同”的 V1.72 小步，再重跑包 1：

1. 把最终推荐改为自带逐对关系的选单；每个已选 Aha 对已选 Chapter、其他已选 Aha 都必须给出有引用的 `SAME_STORY / DISTINCT_STORY`。缺失或 `UNRESOLVED` 不得标记为完整可发布。
2. Aha 提名绑定一个原子事实/证据 Window，禁止一个 Aha 把同视频多个可分事件整体交给 Writer。
3. Writer 的 Aha 正文 schema 设 `maxLength: 24`，维持一次调用、无重写；超限结果不再标记主文案就绪。
4. 对 OCR 专名和动作强度增加通用证据置信处理，不增加古镇、小狗、石板路等场景词规则。

这四项来自本轮真实错误。C2 是否应拆分会在完成上述主干约束后由同版全链结果继续验证；本轮不把一个案例直接固化成场景规则。
