# Codex Diary One｜算法全链路综合复核与优化建议

日期：2026-09-07。性质：分析与建议，不是新冻结合同，也不代表已实施、已上线或质量验收通过。

## 1. 先给结论

**保留现有骨架，优先修正“记忆编辑决策”，不要推倒重来，也不要继续围绕单张图补规则。**

目前已经具备“读取素材 → 观察事实 → 组织候选 → 精选画面 → 写作 → 可追踪交付”的有效骨架。真实素材证明它能形成合理 Chapter，也能在四个素材中去掉一个重复项而保留 Chapter。

但核心质量仍未通过。主要问题不是“所有图都看不懂”，而是：

1. 看到了什么，尚不能稳定转化为“这是哪一段具体经历”。
2. Aha 在真正评选前就受到事件分类限制，普通生活发现的入口偏窄。
3. Chapter 与 Aha 分别选出后，没有可靠完成“这两张卡是否值得同时存在”的判断。
4. 文案虽然绑定事实编号，却仍可能借用未经支持的细节、先后关系；短文案也没有稳定聚焦。
5. 当前测试更擅长证明“运行与接口成立”，尚不足以证明“不同用户愿意保留这些记忆”。

**最值得投入的下一步是：让同一个编辑决策环节，基于真实证据，同时确定具体经历、独立发现和各张卡的表达重点，再交给精选与写作执行。** 这不是要求一个大模型一次吞下全天原视频，也不是增加一串审查 Agent。

## 2. 我们究竟在为谁解决什么问题

### 2.1 核心目标

用户不是想获得一份“摄像头识别到了哪些东西”的报告，而是希望设备替自己留下：

- 今天值得回看的几段经历；
- 容易忽略、但看见后会觉得有意思的生活小发现；
- 少量不重复的好画面，以及自然、可信、简短的表达。

因此，成功不是输出数量够了、标签齐了或所有请求都返回成功，而是：**经历分得清、重要内容不漏、画面有区别、文字不乱编，用户愿意留下。**

### 2.2 用户类型：按需求覆盖，不按场景写模板

目前没有足够用户研究支持年龄、收入等人口画像。更适合用下列需求维度组织验证，而不是假装已经完成市场分群。

| 需求类型 | 用户希望留下什么 | 算法容易走偏的地方 |
| --- | --- | --- |
| 旅行、探索、文化发现 | 同一次旅途中不同的具体体验 | 全部归成“旅游”；或因对象不同把同一段漫步拆碎 |
| 普通生活、通勤、居家 | 平常一天中值得一笑、值得记住的小片刻 | 因为没有“大事件”就没有 Aha |
| 家庭、朋友、共同活动 | 一段相处及其中有意义的动作或互动 | 把同一故事的高潮再发布为重复 Aha |
| 兴趣、户外、长期重复活动 | 熟悉活动中今天不同的地方 | 只按类别去重，忽视真实差异；或每天输出相同套话 |

这些类型可以重叠。它们是未来真实数据的覆盖维度，不是“旅游必须写烟火气、家庭必须写动作”的规则。目前也还不能声称系统已经知道某个用户的个人兴趣。

### 2.3 已有目标、要求与限制

| 项目 | 应坚持的定义 | 本次复核的提醒 |
| --- | --- | --- |
| 参考高强度日 | 5 小时佩戴，150 个 Auto Video、20 张 Manual Photo、16 个 Manual Video，共 186 个素材 | 视频合计约 34 分钟，不是 5 小时视频。Auto 只采样佩戴时间的 7.5%，不能补写没拍到的过程 |
| Chapter | 丰富日尽量 3–4 个；每个 3–5 个有贡献的素材；第 5 个是严格例外 | 不是数量配额，也不能为凑三个混合不同经历 |
| Aha | 主动寻找生活发现；普通日争取 1–2 个，丰富日 2–3 个 | 少素材不等于没价值，但不以造故事满足数量 |
| 重复素材 | 可以抑制 Manual 在记忆中的重复，但保留独立 Manual 窗口和事实记录 | 去掉四个中的一个，不应连带删除仍成立的三个素材 Chapter |
| 叙事关系 | Chapter 内发生的独立发现可以另作 Aha；同一故事不能重复占位 | “时间上属于 Chapter”与“故事上重复”是两回事 |
| 表达 | Chapter 一两句话，有具体画面，也允许少量氛围；Aha 约 20 字，20% 浮动可接受 | 不列尽对象，不靠反复重写抽卡，不硬截断；超过长度仍需评价是否失焦 |
| 输入可信度 | 当前测试可无 GPS、无拍摄时间；一次导入视为一个测试记忆日 | 导入顺序不是拍摄时间；不能生成“先到这里、最后离开”等未经支持的旅程 |
| 用户交互 | 用户 Sync 后后台无感处理，不增加上传确认操作 | 生产中的增量触发、任务恢复仍需独立验证 |
| Auto 证据 | 手机固定取三帧；保守 1-or-3 上传；单帧无法确认就放弃该候选，不追补两帧 | 不因本次优化重新引入补传、完整原视频上传或完美记录目标 |
| 多次导入 | 约 1.5 小时有效 Auto 覆盖可进入准备，约 2 小时是默认生成参考；特殊触发另按既有定义 | 正式日内累计要维护稳定记忆身份，不能把多个批次直接当多个独立全天 |
| 成本 | 历史规划为 cohort 平均 ≤ US$1.50/用户/月，工程期望约 US$0.90、内部预警约 US$1.20 | 不是每位重度用户硬上限；按最新指示，质量优先，不做苛刻微观省钱 |
| 海外 | 核心市场在海外，现阶段先中文测试 | 英文等语言必须另做表达与长度验证，不能机械套用中文字数 |

有两项既有定义不能假装已经统一：旧版无 Chapter 的 `HIGHLIGHT_DAY` 仅允许一个强 Aha，当前代码也保留这个限制；而后续目标更强调少素材、多种生活发现。另外，产品允许第 5 个 Chapter 的例外，当前研究代码上限仍为 4。这些需要明确继承关系，而不是暗中改值。

## 3. 当前实际 workflow：每一步真的做了什么

这里描述的是当前 X02 研究实现，不把规划文件中的全部 S01–S13 能力冒充已经落地。

| 环节 | 当前实际工作 | 模型与规则的作用 | 重要边界 |
| --- | --- | --- | --- |
| 输入与标准化 | 接收素材，解码视频，生成抽帧与素材清单，保存来源标识 | 本地程序执行 | 手机测试素材与未来 Auto 采样分布不同；当前样本无可信日内时间 |
| S04 事实观察 | 小批量看图；一个原素材产生一份观察，包含事实、质量和场景/事件等分类 | 视觉模型；当前上限每批 3 个素材、18 帧、4 MiB | 视频多个 Window 汇入同一素材观察，不是完整的逐 Window 事件理解 |
| 初步角色与边界 | 根据质量、事实支持给出 KEEP 等角色；相邻观察生成连续/边界提示，再组 Moment | 程序规则 | 当前边界依赖导入顺序和类别；DEFER 在此路径被分开处理，不等于已实现全部冻结的四状态/待定块推理 |
| S05–S07 结构规划 | 从事实文字提出 Chapter、成员贡献、Aha 及二者关系 | 一次结构模型调用，当前主要看文字而非重新看图 | 要求“具体经历优先”已写进 Prompt，但真实结果仍违反；不是供应商强制语义约束 |
| S08–S09 对应的候选与集合选择 | 检查引用、支持度，算 Chapter 分数并选择集合；随后挑 Aha | 程序负责合同和排序，语义主要继承上游判断 | 阶段状态完成不代表已实现规划中的全部证据补强；Chapter 先选、Aha 后选 |
| S10 精选画面 | 对多于三个成员的已选 Chapter，进行视觉排序/去重；允许保留合法的 3–5 个子集 | 通常每个相关 Chapter 一次视觉调用；失败时质量排序兜底 | 每个原素材当前仅展示第一张已引用证据帧；三个成员不会进入同样的视觉对比 |
| S11 写作 | 接收最终可用事实与内容提示，生成标题、短文案等 | 正常路径一次 Writer；目前实验角色使用同一 Qwen 模型快照 | Writer 不应再决定两段经历是否应合并；软长度放行不代表文字质量合格 |
| S12 校验与交付 | 校验格式、来源/事实引用、句数等，输出卡片、标签与诊断信息 | 本地确定性程序，不新增模型调用 | “引用存在”只能证明来源关系，不能证明每个措辞都由图片支持 |
| S13 与生产日内处理 | 研究结果提供证据预览；完整产品媒体生成与长期日内增量能力另有规划 | 不应算作本轮已验证能力 | 当前真实实验未执行完整 S13；不能等同佩戴设备到正式成片的生产全链路 |

释义：Window 是一段视频中用于观察的短时间窗口；Moment 是初步聚合的片段单元；Storyline 是一张 Chapter 围绕的具体经历；Beat 是一个素材对这段经历的贡献；Writer 是把已选事实写成人话的模型步骤。Embedding 是把图像/文字变成可比较的数值向量，适合辅助找相近内容，但“向量接近”不等于“同一段故事”，目前也不能把相邻类别账本称为成熟的语义向量聚类系统。

## 4. 已经具备的优势

### 4.1 骨架分工基本正确

把看图、组织、精选、写作分开是有意义的。原本观察错、分组错、文案错，会变成一种笼统的“AI 不好”；现在能够追到责任环节。应保留分工，而不是合并成一个不可分析的巨大 Prompt。

### 4.2 不再只按相同对象聚类

V1.68 素材包 1 的古巷、林径等 Chapter，已有不同对象共同支持一段经历的正向结果。古建筑外观、街巷和细节不是必须互相长得相似才能成章。这个方向比按标签或画面相似度硬分组正确。

### 4.3 重要的工程误杀已得到局部修复

V1.67 将重复提交的成员/事实列表收敛为单一结构来源，减少了“语义成立、却因重复字段不一致被拒绝”的问题。素材精选也已经允许四个成员变三个；素材包 2 的骆驼 Chapter 有真实的去重后保留案例。不能将这些已修复问题继续列为当前未修复缺陷。

### 4.4 保留内容与质量评价开始分离

不再因为一次轻微超长就把全天内容清空；系统能记录未决关系、失败来源、模型阶段与 token。这里的可追踪性很有价值。下一步是利用这些信息改善决策，而不是增加更多日志后就宣布质量通过。

### 4.5 运行证据足以支持有针对性的实验

现在有真实原素材、证据帧、请求、响应、模型版本、耗时与 usage，可以比较同一输入的不同方案。问题不是缺少再写一套宏大架构的材料，而是要把实验问题收窄，并建立独立的用户评价标准。

## 5. 主要缺陷：按对用户结果的影响排序

### P0-A｜“主题相同”仍会被误当成“同一段经历”

**真实发生：** 素材包 2 的“烟火里的食光”把室内餐食与夜市小吃合在一起。模型解释本身就是两类饮食场景，并自行构造从正式用餐到街边小吃的逻辑。实际五张图支持室内与夜市两组；夜市还存在被遗漏的餐车远景，但该图清晰度较弱，仍需精选评价，不能仅因凑到三张就保证可成章。

**机制：** 结构模型依赖压缩后的事实和标签；“具体经历”约束是提示，不是已验证能力。程序可以检查三张图片都存在，不能检查这三张是否真该组成同一段经历。后续精选与 Writer 已处于既定 Chapter 内，通常不会重建分组。

**优化：** 主干先明确每组到底让用户回忆哪件事、每个素材有什么连接证据；同时保留真实可支持的子组。比较结构模型能力与必要画面输入，不再只追加“不要混合”的提示。不能写“室内室外永不合章”等新特例，因为连续活动确实可能跨场景。

### P0-B｜Aha 的普通生活入口偏窄

**代码机制：** 当前模型提出的 Aha 最终也要经过事件类别白名单、MEDIUM/HIGH 显著性、KEEP 等过滤。每份素材观察最多形成一个 Aha 候选。`NONE` 或未进入允许类别的内容，在真正比较“值得不值得留”之前就可能出局。

**真实线索：** 素材包 2 中乘车、耳机、相机等日常画面可供人评价是否值得记住，但相应观察是 NONE/NONE，未获得同等的 Aha 比较机会。这不意味着它一定应入选，而是不能用“模型最终没选”证明用户不感兴趣。

**优化：** 分类和显著性可以辅助，不应独占候选资格。先允许有清楚证据的普通发现进入同一轮编辑评选，再判断独特性、兴趣与画面表现。不要新增猫狗、食物、旅游专用模板，也不要从“尽量找到 Aha”滑向“每包强制补一个”。

### P0-C｜Chapter/Aha 的独立价值判断没有闭合

**真实发生：** 素材包 1 的同一只狗、同一林径、同一素材，同时作为 Chapter 的核心画面和 Aha；素材包 2 也有鹿与食物的同故事重复。

**代码机制：** 已经明确标为 SAME_STORY 的关系会阻止重复，但漏交/无效关系成为 UNRESOLVED 后仍可共存。一个关系标签即使写了 DISTINCT，也不能自动证明其理由成立。程序中的 Chapter–Chapter 冲突主要检查原素材重叠，也不能识别“不同照片讲同一件事”。

**优化：** 一次编辑规划同时确定卡片集合与各自要表达的内容；对实际重叠或核心事实接近的组合明确回答“新增了什么记忆价值”。不要求所有 Chapter×Aha 机械填写巨大矩阵，也不把所有未知关系直接判死刑。最终精选改变核心表达时，按已经记录的关系重新计算；没有新证据不启动无限重审。

### P1-A｜评分在奖励易计算的代理指标，不完全是用户价值

**代码机制：** 当前 Chapter 分数约为：40% 质量 + 30% 事实支持 + 20% 成员数量深度 + 10% 情节角色多样性。质量、支持度仍有模型自评成分。Aha 排序首先依赖显著性等级；“特异性”对已通过类别筛选的候选大多相同。

**待验证判断：** 这些指标可能偏向多素材、多情节角色的组，而不是更清楚、更值得留下的经历；也可能鼓励模型把普通漫步解释成开端、高潮、结尾。不能仅凭公式断言它就是某次混合错误的唯一原因。

**优化：** 用人的真实保留/删除、候选对比判断来校准。质量与事实支持是基础条件；主要比较经历清晰度、各素材新增贡献和用户记忆价值。三个恰当素材不应天然输给五个相近素材。不必马上换一套自创权重。

### P1-B｜事实来源可追踪，但内容未必真正受事实约束

**真实发生：** 已有“项圈轻晃”等超出被引用事实的描述；无可信日内时间时出现“最终转身离去”等时序外推；部分源观察自身也存在属性冲突。不是全部错误都来自 Writer，也不是把模型换大就能跳过定位。

**机制：** 一个合法事实 ID 可能关联一段很长的描述，既包含画面事实，也混有解释。下游引用了这个 ID，不等于句中每个动作或时间关系都得到支持。当前结构化格式约束解决的是“怎么返回”，不是“说的一定对”。

**优化：** 事实与解释分开；关键动作/关系绑定具体既有证据帧；不可信的素材间时间只作为未知，不靠导入顺序补齐。编辑选定一个表达核心，Writer 负责语言，不新增故事。只针对真实复现的错误设计验证，不建设颜色、石板路、动物名称等禁词表。

### P1-C｜精选看到的证据可能不足，短文案仍可能失焦

**代码机制：** S10 对每个视频通常只取第一张已引用帧比较；恰好三个成员时不做同等视觉对比。现有保护机制能保住 Chapter，但也可能保留重复或不代表视频主要内容的画面。

**真实发生：** V1.68 的 Aha 仍有约 40–53 字的输出。软长度避免了清空结果，这是进步；但不能因此认定已达到简短自然的产品目标。

**优化：** 从已上传帧中选择与候选关键事实相符的画面，不请求补帧；去重区分“同一画面重复”与“同一对象的有意义不同贡献”。文案优先表达一个核心意思，可带一个有意义的细节，不固定列三件 object，也不增加第二轮随机重写。超长率是诊断指标，不是唯一质量指标。

### P1-D｜评估尚未形成独立的用户质量闭环

**真实状态：** 三套素材总计 102 个原素材、187 帧；反复跑很多次仍主要是三套开发样本。它们可以发现真实错误，但不能证明跨用户泛化。连续版本有时同时重新识别、改变 Prompt 和结构，不能把结果差异全部归因于某一改动。

**优化：** 分开“定位原因的阶段对照”和“验收质量的完整新跑”。前者固定事实观察，只变一个待测因素；后者每个流程重新执行。评分绑定具体 Chapter、具体素材、具体句子，并留下用户认为遗漏的真实内容。新用户/新旅程单独留作未见测试集。

### P2｜生产与版本完整性不能被研究结果替代

**代码/交付边界：** 当前尚未用真实设备日内多次导入证明时间边界、增量修订、长期去重、最终媒体交付与恢复能力。研究候选、Web 接线、App 封存包是不同对象。一次请求的超时与调用次数上限，也不等于整个任务有可靠截止、断点恢复和取消。

**优化：** 保留已经验过的交付包，在新候选质量通过后才创建新版本替换。每次用户测试展示实际算法、Prompt、模型与源码指纹，避免再次出现“以为测新版，实际上跑旧版”。生产完善要安排，但不能用上线工程掩盖当前内容质量问题。

**判断：目前不宜为省一点 token 牺牲主干质量，也没有依据把本项目已知模型费描述成失控。** 但是这两个小样本不等于 186 个素材的设备日，更不等于用户群体月成本。

### 6.2 真正需要提前注意的规模风险

- 按当前每批最多三个素材，186 个素材仅 S04 就至少需要 62 批；帧数或字节上限可能进一步增加批数。这是由上限推算的容量提醒，不是实测日费用或时延。
- 当前结构候选数量和单 Chapter 候选成员都有上限，单候选最多 12 个成员。长时间、高密度的同一经历，需要验证候选压缩有没有提前漏掉最好画面，不能只看最终 3–5 张是否合规。
- 所有阶段共用同一个模型快照，有利于接入简单，但不代表它同时是视觉、结构与写作的最佳性价比。最值得先做模型能力对照的是“结构规划”，不是因为文案不够美就先把 Writer 换一圈。
- 当前时延主要在观察、结构与精选，而不是 Writer。优化需看实际阶段等待、批次并发与请求大小，不能凭 token 数猜耗时。
- 正式多次 Sync 应复用同一版本下已处理的旧素材，处理新增和受影响的记忆。**这种生产缓存，与正式实验要求重新执行全链路不矛盾。**

建议继续记录五类成本：观察、结构、精选、写作、重试/失败；另外单列上传量、标准化耗时和服务成本。等质量方向确认后，用真实设备日、实际活跃天数和增量导入频率估算 cohort 月成本。现阶段不新增苛刻的低费用质量阻断。

## 7. 建议的优化架构：让编辑决策负责到底

建议保留下面这条主干：

**素材与可信信息 → 事实观察 → 具体经历与生活发现候选 → 当天记忆联合选择及表达重点 → 精选已有画面 → 一次短写作 → 基础校验与交付。**

其中最重要的变化不是增加步骤，而是明确谁有权决定内容。

### 7.1 观察负责“看清”，不提前决定“值不值得记”

保留有证据的主体、动作、关系、环境，以及支持它们的既有画面。类别、画质、显著性作为辅助信息。除了无法解码、没有可用证据等基础限制，不能只因一个事件枚举就让有意义的日常画面失去参与评选的机会。

例：相机、耳机、车内人物不必先被认成某种“重大事件”，才有资格与其他发现比较；最终是否值得 Aha 仍交给编辑选择和真实用户评价。

### 7.2 编辑负责“哪些卡值得共同留下”，不只是提交候选名单

现在 S07 已经同时提出 Chapter 和 Aha；问题并不是少了一次“同时生成”的调用。问题是其后又经过独立类别门槛、不同排序和不完整关系处理，最终集合不一定保留原有编辑意图。

建议在同一结构环节里明确三件事：

1. 每个 Chapter 的具体经历、成员的真实贡献，以及支持不充分时的候选子组。
2. 每个 Aha 最值得留的一个点，以及与已选 Chapter 是否增加了不同价值。
3. 优先发布的集合和少量备选；程序检查引用、素材数量和明确冲突，不再用未经校准的情节角色分数替代编辑判断。

不是让模型填无限长表格。素材 ID、成员集合等能由程序推导的继续由程序推导；只对真正相关的卡片解释共存关系。也不是立即把全部工程判断交给模型：文件有效性、引用合法性、数量边界和版本一致性仍由代码负责。

例：古镇漫步 Chapter 与途中一个有独立发现价值的甜品 Aha 可以并存；如果 Chapter 的中心本来就是这次甜品体验，再换一种文案不能算新增故事。这是共性原则，不是甜品例外规则。

### 7.3 精选负责“把该表达的内容挑好”，不能用补足数量修复分组

画面去重应比较新增贡献，不是看到两个建筑就删一个，也不是相隔二十分钟就自动视为不同内容。优先选择与已选事实对应的现有帧；对长视频不能只让第一张图代表全部内容。

例：四个素材中两张是近乎同一画面的餐车，留下更好的一张和另外两张有不同贡献的素材即可。如果剩下三张仍支持同一经历，保留 Chapter；如果本来就没有三个合适素材，不从室内用餐拉一张补数。

### 7.4 Writer 负责“说得自然”，不重新创作事件

输入应突出一个核心意思和少量必要事实，其余识别信息继续保存在事实账本和标签中，不要求正文全部表达。定语是否保留，看它是否改变这段记忆的辨识度或情绪理解，而不是统一禁止颜色、材质或位置。

例：某个颜色对辨认独特场景有意义时可以保留；只是桌面、衣服、杯子的常规外观时可以省略。取舍标准是“删掉它，用户是否还准确理解这张卡”，不是某类形容词永远不准出现。

保持一次主写作、不循环抽卡、不硬截断。后处理只做确定性格式处理；如果要改写实际含义，那就是语义决策，不能伪装成无风险的字符串修复。

### 7.5 标签服务检索，不支配故事

保留 canonical tag 的稳定概念标识、来源和版本；允许暂时未知或待归一化，不能为了填满四个分类而赋予错误标签。自然语言记忆与检索分类不必一模一样。

例：一张“街边小吃”的卡可以有地点/活动等检索信息，但不应仅因观察分类投票而落入不相干的工艺品类别。未来依据真实检索需求扩充概念体系，不按每次举例增加一个特殊运行时词条。

## 8. 分阶段执行方案：每段都有可介入的结果

以下是建议，不是本轮已实施变更。不要一次把所有改动合成一个版本后才让用户看结果。

| 阶段 | 做什么 | 阶段交付与检查 | 明确不做 |
| --- | --- | --- | --- |
| A：固定现状与真实评价 | 用当前输出建立小规模评价表；锁定一组真实错误和正向案例；厘清两个旧合同冲突 | 每条问题都能点到卡片、图片或句子；正向结果也受保护 | 不继续构造图像未验证的语义反例；不重建大型审计体系 |
| B：主干结构对照 | 先固定真实观察输入，检验“候选资格、联合编辑决策、结构模型能力”这些因素；每组对照只改变一个因素 | 室内餐食/夜市不因饮食主题混合；古镇多对象仍可成章；普通发现参与评选；同故事不双发 | 不同时更换观察模型、Writer、阈值和整套 Prompt；不以阶段成功冒充全链路成功 |
| C：完整链路验证 | 选出一个有依据的候选后，三包都从原素材完整新跑；用预先约定的有限轮次检查稳定性 | 展示所有运行，包括失败；逐卡、逐素材、逐句评价；列成本/时延与相对基线变化 | 不挑最好一次；不为得到漂亮数量反复重跑；不把旧缓存结果称为完整新测 |
| D：未见用户与设备日 | 再引入新用户、新旅程、连续普通日及真实设备分布 | 看遗漏、误合、Aha 保留意愿、日内稳定性是否可接受，再决定接入新版 | 不用同三包调参到满意就宣布泛化；不自动触碰 App/SDK/公开部署 |

**B 阶段的推荐次序：先修内容决策责任，再按证据决定是否换模型。** 若同样事实在更清晰、精简的结构任务下仍然把不同经历混合，再对照当前供应商的更强结构能力；如果事实文本确实丢了决定性连接信息，再比较加入少量相关既有画面的收益。避免同时改变三个因素，最后不知道是哪一个有效。

阶段 C 的“完整测试”依然执行每一个已经实现的流程。阶段 B 的重放只是低成本定位原因，不是额外的产品 Gate0，更不是替代用户要求的完整验收。后续若要改变当前已冻结的中止条件，应先明确新的有限测试矩阵；本次分析不擅自恢复已经停止的 V1.68 付费运行。

### 真正需要用户决定的节点

大多数引用校验、版本归档、测试执行不需要用户反复确认。以下才属于产品取舍：

- **无 Chapter 的一天是否允许两个或三个独立 Aha。** 建议不因没有 Chapter 就机械限制为一个，仍按真实价值选择；这需要覆盖旧 `HIGHLIGHT_DAY` 定义。
- **同一故事只能保留一种形态时，是否永远 Chapter 优先。** 建议不永远优先：有时一个很好的 Aha 比勉强凑出的 Chapter 更值得留；但不能让系统随意把已经发布的稳定 Chapter 换掉。首轮编辑与日内修订应分别定义。

第 5 个 Chapter 目前属于已同意但尚未完整落地的例外，不必再次讨论是否允许，后续明确实现和验收即可。具体经历优先、允许少量氛围、20% 字数容差也无需重新征求同意。

## 9. 怎样用真实素材形成学习闭环

### 9.1 先做评价与数据积累，再谈训练模型

三套素材适合做开发回归，不足以训练或证明通用记忆算法。第一阶段优先把主干职责、模型输入和评价做好；大量真实标注显示稳定共性问题后，再判断需要排序校准、提示调整、模型替换还是微调。

“训练”不必一开始就是训练一个大模型。用户的选择可以先用于校准候选排序和风格偏好；只有任务定义稳定、数据量与授权范围足够时才评估微调。不能承诺通过训练就保证所有用户满意。

### 9.2 评价必须落到可修改的最小对象

| 评价对象 | 人具体评什么 | 怎样利用 |
| --- | --- | --- |
| 一天 | 有没有漏掉本人最想留下的经历/发现；整体是否愿意保留 | 衡量有效覆盖，而非仅统计卡片数 |
| Chapter | 是否一段清楚的经历；是否应该拆分或合并 | 改进具体经历组织与候选集合 |
| Chapter 内每个素材 | 属不属于这段经历；有无新增贡献；删掉是否更好 | 改进去重、精选与“至少三个”的实际质量 |
| Aha | 值不值得单独留下；和其他卡是否讲同一件事 | 改进发现能力与独立价值判断 |
| 文案的具体句子/短语 | 事实对不对、是否自然、哪里多余、是否过度解释 | 区分观察错误、组织外推与表达问题 |
| 标签 | 含义准确吗；未来能否帮本人找回来 | 校准 canonical 概念与来源绑定 |
| 等待过程 | 是否知道在处理什么；中断后能否继续；是否等待过久 | 改善工程体验，不混入语义评分 |

一条可用反馈至少包含：运行版本、素材包/用户、卡片 ID、相关素材 ID、问题类别、具体意见、可选修改/保留选择。关联原证据帧，区分算法自动判断与用户意见。

例：对“烟火里的食光”的反馈不是“聚类 2 分”，而是“移出室内餐食 16、17；夜市 18、19、20 作为候选子组检查，18 清晰度较差需评价；如果不能选出三个合格素材，不成章；独立小吃是否值得 Aha 另评”。这是一条真实错误的修正建议，不是未来所有餐食场景必须照做的规则。

### 9.3 通用质量与个人偏好要分开

- 误认对象、编造动作、把两个不相关经历拼成一段，是应优先修复的共性质量问题。
- 是否喜欢拍建筑细节、是否更想保留家人互动、偏好朴素还是轻微氛围表达，属于个人偏好。不能把单个人的低分全都升级成所有人的硬规则。
- 同一组素材可能有多种合理切分，应允许可接受方案集合，而不是只有一份固定“标准答案”。对边界争议保留意见差异。

### 9.4 避免把测试集“训练熟了”

按用户与旅程/日期划分开发集和未见测试集；近重复照片、同一视频的不同抽帧不能分散进训练与测试，制造假泛化。当前三包的多轮结果不能当成新增用户样本。

正式比较时固定模型快照、Prompt、代码和输入清单，预先定有限重复轮次；保留全部输出，不择优上报。先人工认可评价标准，再逐步引入模型辅助评分；模型评分不能取代真实用户保留意愿，更不能由同一个生成模型自行宣布验收通过。

建议持续观察：经历误合与遗漏、成员相关性与重复率、Aha 独立性与保留意愿、事实错误、文案自然度、运行间波动、时延和完整费用。当前样本不足，不在这里凭空设定“达到 95% 就上线”的阈值。

### 9.5 关于过程展示与数据使用

向用户展示可核验的决策摘要：看到了哪些事实、为何放在一起、某个素材为何没选、Aha 与 Chapter 有何不同、各步骤花了多少时间和 token。不要把长篇模型自述或内部思维过程当成正确性证明。

现有三包已获得测试使用许可，本次不重复询问。未来收集其他同事或用户的素材时，另行明确测试、留存、标注、外部模型与训练用途，不能从“允许测试”自动推导“允许长期训练”。这些是新数据使用边界，不是在当前质量研发前重新堆一套阻断流程。

## 10. 对研发方法的反思与最终建议

过去一部分工作解决了真实工程问题，但也在局部文案、合同字段和审计细节上停留过久。检查点增多不等于核心质量改善；阶段成功也不能代替用户看到的最终记忆。这个工作方法需要纠偏，而不是再用更多确认节点补救。

后续每轮只回答一个主问题，并同时交付四样东西：**真实问题、共性机制、有限改动、对完整结果的影响。** 如果连续若干局部修改仍没改善主要体验，就回到素材观察和内容组织，而不是继续改一个词。

最终建议：

1. 保留已经有效的抽帧、事实来源、结构分工、子集精选、一次写作和运行追踪。
2. 把近期主要精力放在“具体经历组织 + 普通生活发现入口 + Chapter/Aha 联合选择”。三者共同决定用户最后看到了什么。
3. 文案、标签、性能按主干结果推进，不以解决某张图的一句话作为长期主线。
