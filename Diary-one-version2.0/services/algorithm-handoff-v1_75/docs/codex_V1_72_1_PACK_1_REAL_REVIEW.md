## 3. 已真实通过的 V1.72.1 修正

### 3.1 Aha 确实锁到一帧

三条 Aha 均绑定一条事实和该事实中的一个焦点帧，最终 `selected_media` 也都只含这一帧。原始事实即使包含两帧，最终卡片不会再把整个事实的多帧全部展示。程序只验证帧属于事实，没有自己理解或切割画面。

### 3.2 24 字成为真实唯一出口

Plus Writer 一次返回的三条正文都是 11 个可见字符，本地验证全部通过。没有第二次 API 改写；没有调用确定性 Aha 兜底；公开状态是 `READY_PRIMARY_COPY`，不再出现 V1.72 的长事实绕过硬门槛。

这证明出口错误已修复，但不能证明 11 字文案本身自然或有吸引力。长度合格与内容好坏必须分开评价。

### 3.3 Writer 模型路由按合同生效

S04 和 S10 仍用 Qwen VL Flash；S07 和唯一一次 S11 使用 Qwen3.7 Plus。Writer 本轮费用约 ¥0.02309，相比 V1.72 Flash Writer 约 ¥0.00267 增加约 ¥0.02042；整轮仍未显著超过当前研发期可接受范围。

## 4. 当前最主要的结构性问题

### 4.1 “不同对象”再次被当成“不同故事”

三条 Aha/Aha 关系的理由分别是不同食物、不同摊位位置、摊位与茶店不同。它们证明的是实体不同，而不是用户体验和叙事职责不同。最终三条正文又都采用“招牌写着什么”的同一表达模式。

因此关系矩阵的字段闭环已经完成，但模型对 `DISTINCT_STORY` 的执行仍然停留在对象分类层。不同店名或商品名不能自动成为三条不同 Aha；需要比较的是用户回看时感受到的经历是否真的新增。

### 4.2 “独立值得回看”的一句提示没有转化为可执行编辑取舍

Prompt 已明确仅有地点标签、背景说明或分类信息不足以成为 Aha，模型仍然把三处商业文字都选满。原因不是缺一句同义提示，而是当前 S07 同时承担 Chapter 分组、Aha 提名、最终选单和 12 条逐对关系，模型可以用“实体不同”快速完成形式合同，却没有对 Aha 集合做足够深的价值比较。

不应继续堆叠“小吃、商铺、招牌”等场景规则。下一步应把“Aha 候选发现”和“Aha 最终集合编辑”拆成可单独检查的职责，让最终编辑明确比较体验价值、故事模式和整组多样性。

### 4.3 关系证据没有完整到达 Writer

市场 Chapter 与三条 Aha 的关系在 S07 中存在并通过，但 S10 精选后，旧的 Writer 投影要求关系引用的全部 Chapter facts 都仍在精选素材中；因此这三条最相关关系被标记 `FINAL_RELATION_REFERENCES_OR_REASON_UNAVAILABLE`，没有进入 Writer 输入。该问题没有造成这轮长度失败，但会削弱 Writer 避免 Chapter/Aha 重述的能力。

这是跨阶段交接问题，不应通过扩大 Writer 的全部事实输入来掩盖。下一阶段需要单独设计：S10 后如何把已经存在的关系，机械地重新绑定到最终保留的事实范围，同时不生成新语义。

## 6. 阶段结论

- 接受：焦点帧引用合同、单帧 Aha 展示、24 字本地硬出口、无 Aha 兜底、一次 Plus Writer、完整关系字段。
- 不接受：当前三条 Aha 的整体质量与多样性，以及市场 Chapter/Aha 关系到 Writer 的交接完整性。
- 不做：不继续包 2，不加场景关键词，不反复调用 Writer，不把本轮 3C/3A 冒称为产品可用。
- 下一建议：先讨论并设计一个独立的 Aha 集合编辑步骤；输入只包含已有 Chapter、Aha 候选事实和焦点，不重新看图、不重做识别。它负责选 0–3 条真正值得回看且故事模式不重复的 Aha，并输出最终逐对关系。之后再单独修复 S10 后关系投影。
