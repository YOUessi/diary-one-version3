# codex D2｜整日编辑决策短设计 v0.1

承接V1.70三包真实复盘。只在算法仓库新增设计记录，不重开既有产品定义，不改运行代码、不调用模型、不切Web/App。

## 1. 这次真正改变什么

**从“列出候选并分别排序”，改为“明确推荐一组互相补充的Chapter与Aha，并交代每张要表达什么”。**

全链位置：素材与抽帧 → S04事实 → **可用素材范围 → S07整日编辑方案 → S09执行方案** → S10精选 → Writer表达 → 预览。

粗体是下一次最小实施的主体；本设计同时定义后两步如何接收内容重点，但视频代表帧、超过12件的候选组选图、Writer语言策略分别在后续步骤实现。不把设计完成说成全链已修复。

| 当前问题 | 本设计的变化 | 真实案例 |
|---|---|---|
| 事件类别先决定能否比较Aha | 有可用证据的素材都可被编辑考虑，标签不再独占入口 | 包3三人合影49为NONE，51为DISCOVERY；不能仅因此决定谁有比较资格 |
| 两份排名经过程序过滤，剩余项补位 | 明确交出推荐Chapter名单与推荐Aha名单，作为一个组合解释 | 包3三个园区片段不因园区章落选而自动占满Aha |
| 有主题提示，但后续可能改变重心 | 区分“计划表达重点”和“最终素材实际能支持的重点” | 包3计划包含比赛与颁奖，最终不能只有庆祝却声称已完整兑现 |

以下案例均来自真实输入和已归档结果，不是新构造的模型错误；建议不是预先规定唯一正确名单。

## 2. 第一步：把“有资格比较”与“值得推荐”分开

### 2.1 三个层次

1. **可比较素材：** 沿用现有基本可用性和事实支持条件（当前KEEP、具有STRONG/MODERATE事实）；不要求特定事件类别或MEDIUM/HIGH事件等级。没有事实的素材不会因为放宽入口而变成候选。
2. **Aha提案：** 编辑模型从全部可比较素材中主动找小发现，包括Chapter内、Chapter外、未成章的内容。明确是哪件素材、哪些事实、值得留下的具体内容。不是每张图都要生成提案。
3. **推荐Aha：** 只有被整日方案明确选中的提案，才进入后续输出。可比较、提出备选、实际推荐，是不同状态。

场景、对象、事件类别仍可保留作理解/检索提示；它们不是兴趣分，也不单独决定入选。Manual可以作为用户主动采集的背景，不免除去重。

**例：** 包3的49号合影能够获得比较机会，但若51号已在所选Chapter中表达同一段相处，49仍可能不推荐。放宽入口不是预定人物胜出。

### 2.2 不用自动候选替代编辑发现

V1.70包3没有原生Aha提案，但程序根据事件标签生成了18个候选，最后按排序留下三件。新研究路径不再让这些自动候选直接填充输出名额；旧事件信息最多是编辑参考。

若模型没有推荐Aha，保留它的实际解释和原始素材供评价，不把“没有推荐”证明成“素材没有价值”，也不靠自动凑卡或重复API调用补数。实验必须检查漏选，防止“更多素材有资格、最后反而更少认真找发现”。

**例：** 包2只有两件室内用餐素材，不能成章，但16号夹肉仍应能作为独立发现被提出和推荐；不能只在Chapter落选清单里被动捡剩余内容。

当前不扩展“一素材多个Aha”或长视频事件切片，先用已有素材/事实编号完成这次验证。

## 3. 第二步：编辑模型给出一个整日推荐组合

仍在现有S07调用中完成，不新增总审模型或第二轮编辑调用。模型可在同一次任务中比较候选，但程序不为每次比较另发请求。

### 3.1 这份方案回答三个问题

- **保留哪几段经历，哪几个独立发现？** 主动考虑普通生活，不为数量凑内容。
- **每张卡主要让人记住什么？** 是具体内容，不是“建筑、旅游、动物”类别名。
- **这张卡相对已经推荐的其他卡，增加了什么？** 理由只服务取舍，不是新事实、个人兴趣评分或最终文案。

先前的成员、事实引用、主题和分工信息继续使用。只对相关、容易重复的卡片说明差别，不要求填写所有卡片两两矩阵，不要求每个未入选素材都写长理由。

**例：** 包3的21、27、30都是园区经历的片段。园区Chapter不推荐时，可以比较是否留其中一个小发现，或它们是否确有不同价值；不能因为有三个名额就全部补入，也不能写成“同一园区最多一个Aha”的规则。

### 3.2 Chapter和Aha是共同取舍，不是先后捡剩余

- 推荐Chapter时，就同时考虑与它相关的Aha。
- 推荐Aha时，不只检查它是否与Chapter冲突，还要比较其他已推荐Aha。
- 已明确的同故事不重复规则继续生效；只是同地点、同对象、同候选章，不自动等于重复。
- 不确定的关系继续可见，不增加“未知即禁止”的硬阻断。
- 不把所有主要经历都必须成章，或所有章内细节都必须变成Aha，写成规则。

**例：** 包1小狗同行已经由Chapter表达，不能只是换一句话再发Aha；包2室内夹肉与夜市是不同内容，可以共同保留。包3夜行与洛阳谁应占第四章，则仍属于真实内容取舍，不能预先指定答案。

### 3.3 程序的职责收窄

S09核查并执行这份明确选单：编号/事实是否有效、Chapter是否至少三件、数量是否合规、是否存在原素材精确重复或已明确的同故事冲突。

它不再用旧价值权重重新排名，不把未推荐候选自动补进名额。主题/标签重叠只作为编辑参考，不自动推导故事相同；具体场景不设排除表。

**例：** 包2两件火锅组即使作为备选留在记录中，也不必出现在推荐Chapter名单里，更不能让四个有效推荐章的选择整体失效。

技术错误与主动不推荐必须区分。局部引用错误应能定位，保留不受影响的有效内容；计划缺损不能伪装成“完整组合已通过”。本步不设计重试循环或新的全面容错框架，解析/兼容细节在下一步实施检查点明确。

## 4. 第三步：把内容重点交给精选和Writer

### 4.1 计划重点

复用Chapter的thesis（这张章主要是什么）和Aha的narrative_duty（这个发现主要说什么），要求表达明确的核心；成员贡献继续由beat_map保存。它们是编辑判断，不是新增事实，也不要求为每张写长故事草稿。

重点不是把全部对象再列一遍，不设置“最多三个object”之类的新规则，也不把某张图片永久锁定为必选。

**例：** 包3足球可以围绕“观赛与赛后庆祝”，也可以明确选择“颁奖庆祝”。两者都可能成立，但选择的素材应与实际决定一致。

### 4.2 精选兑现，必要时如实报告收窄

S10在同组可用素材中选择3–5件，先比较哪些组合更好地保住计划重点；可以去掉重复画面，可以用有相同贡献的其他素材替换。

如果精选后确实只支持较窄的内容，应把“最终可支持的重点＋对应事实”交给Writer，同时留下与原计划的差异；不能让Writer在缺少画面的情况下补写原计划。

这是S10既有调用内的输出职责，不新增语义审核调用。程序能检查事实编号是否属于最终素材，不能据此宣称已证明语义正确。无法判断、未执行视觉比较或明显未兑现的情况进入研究评价记录，不新增自动砍章规则，也不把变化偷偷当作已成功兑现。

**例：** 包3最终若只留下比分、奖杯、庆祝，就不能继续以“比赛动作已经保留”作验收结论。包1碑石若因合理取舍未入选，也不能由程序自动恢复成Aha；要检查本来想保留的发现是否无处体现。

若重点变化影响原Chapter/Aha分工，旧的独立性说明不能继续当作已验证结论。这是后续S10专项必须检查的交接风险；本轮不增加自动重规划、额外调用或用户交互。

### 4.3 Writer只表达实际支持的内容

现有Writer已经只接收最终素材范围内的事实，这项能力保留，不冒充本次新修复。拟议变化是主题提示也对齐最终实际重点，避免仍沿用未被精选兑现的完整候选主线。事实账本保持完整，不物理删除“没写进文案”的事实。

**例：** 如果实际决定表达的是“夹起食物的一个瞬间”，旁边的桌面、配菜、灯光不必都说出来；不因此规定食物场景必须采用某一种情绪词。

这一职责需要后续Writer专项落实；本设计不承诺靠换一段提示立即解决7条Aha全部偏长的问题。

## 5. 必要接口变化，控制在最小范围

| 接口概念 | 拟议变化 | 不变部分 |
|---|---|---|
| 可比较Aha范围 | 从事件合格清单改为全部有可用证据的素材范围 | 保留原素材、观察、事实ID及可用性底线 |
| Aha提案 | 每张推荐Aha需有明确提案；自动事件候选不直接补位 | 复用观察ID、事实ID、narrative_duty |
| 整日选单day_selection | 用推荐Chapter键、推荐Aha键和简短整体理由，替代完整候选排列editorial_order | 不重复提交成员与事实清单；不要求未推荐项排序 |
| 内容交接 | 复用计划主题；后续S10增加最终可支持重点及事实范围，Writer消费它 | 不借用其他卡片事实，不新增长篇故事或评分矩阵 |

这些是接口方向，不是本轮已提交的JSON Schema。下一步需明确版本隔离、缺损选单的处理和兼容路径；旧研究入口与封存记录不改写，新路径不能静默混用新选单和旧排序后声称同一策略。

S07仍主要读已有事实，不能凭本设计修复上游漏看/误识别。S10视频首帧问题、超过12素材退回质量排序的问题必须独立处理；本设计不通过预先砍候选或强拆Chapter绕过这些限制。

## 6. 怎么验证这次不是又加了一段口号

使用已有真实记录，检查四件事：

1. **入口确实改变：** 包3的49等有据素材，不再仅因事件类别被排除；不是强制它成为Aha。
2. **名单确实由整体推荐产生：** 包3园区的三个片段若共同入选，必须是模型明确共同推荐的实际结果，而不是程序补位；理由质量仍需人评价。
3. **既有正向结果保住：** 包2室内/夜市分开、夹肉Aha、三件夜市章；包1小狗同故事不双发。
4. **主线是否兑现可追查：** 包3足球、包1碑石能看见计划与精选差异；素材少了不自动等于质量提高，格式通过不等于内容正确。

“推荐名单被正确执行”只算工程通过。若模型仍把同一园区故事拆成三张没有独立贡献的Aha，即使选单和理由齐全，内容质量也不通过；若真实画面确有不同价值则允许保留，不预先规定只能选一张。组合是否更好须回到画面及用户评价，不能靠模型自称“互补”验收。

这些是实验检查对象，不转成运行时案例词表。若出现Aha变少、遗漏重要经历、新的混组或重复，必须和正向结果一起报告。

下一次实施先落地入口和整日选单；S10/Writer交接仅保留清楚的计划，不冒充后续能力已完成。局部对照用于归因；正式质量验收仍从标准化到预览重新跑全部流程，不以旧回复回放代替。

## 7. 已有产品边界与待后续统一事项

继续沿用：Chapter最低三件、目标三四章；Aha约20字、24字容忍；同故事不重复；无可信时间不编造先后；不追补Auto两帧；不增加用户Sync后的上传操作。不新增兴趣问卷或评分必填交互。

本步不修改现有研究上限4 Chapter / 3 Aha；无Chapter时现有最多1 Aha的限制也不暗改。产品曾允许第5章例外、普通生活Aha的目标与稀素材日上限尚需后续统一。当前三包都有Chapter，这两项不作为本步前置决策；新路径需明确继承，不能在实现时遗忘。

本轮没有必须新增的产品/交互选择。夜行与洛阳、颁奖与比赛重点等偏好先放入具体评价，不为了推进代码强求唯一答案。
