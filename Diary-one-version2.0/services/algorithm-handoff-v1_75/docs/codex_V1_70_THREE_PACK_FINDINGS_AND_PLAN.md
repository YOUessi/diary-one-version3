# codex V1.70｜三包真实验证：综合结论与下一步

日期：2026-09-08。承接 [V1.70研究检查点](codex_CHECKPOINT_V1_70_EDITORIAL_ORDER.md)。
**结论：同版三包各一次真实研究链已完成；新排序接线有效，但整体内容质量仍未接受，不切换Web/App。**

本报告 supersede 包1报告中的“包2/3等待授权”运行状态，不改写历史报告或原始结果。用户明确批准两包抽帧及相关文字向北京百炼发送后，完成包2、包3；没有重跑包1、没有中途换模型或改算法。

## 1. 回到核心目标：不是多出几张卡，而是选出值得看的记忆

目标是让用户从一天的素材中看到清楚、互补的经历与小发现：Chapter通常3–4个、每章3–5个精选素材；Aha提供独立价值，不能只是同一故事的重复。无需完美覆盖所有素材，也不能因为部分图相似便轻易整章删除。

这次实验只验证一个假设：**S07交出编辑优先顺序，S09照此取舍，能否改善最后名单。** 没有同步修S04识别、S10视频代表帧或Writer。

答案分两层：

- 工程上接通了：包1/3两路排序生效；包2Aha生效，Chapter因不必要的完整性要求回退。
- 产品上仍不足：包1/2用同一新S07回复交给旧S09，名单不变；包3名单改变，但出现三张Aha集中在一个落选园区故事的情况。**“排序生效”不是“整体取舍正确”。**

不能把每次新运行的局部好转都记在排序头上：新事实、分组和模型自然波动也会影响结果。

## 3. 已有优势，应该保住

1. **主要经历已有可理解边界。** 包2室内夹肉与夜市不混组；包3山顶古建48不再进入洛阳候选，夜街23–25也进入上海候选。
2. **三件底线与同故事分工能够起效。** 包2夜市三件成章，室内只有两件不硬凑章、保留夹肉Aha；包1小狗和包3金殿不再另发同故事Aha。
3. **不因一处失败清空全天结果。** 102个素材均有事实保留，排序失败有明确回退；但回退范围过大仍需修正。
4. **证据可追查。** 每次模型请求、实际模型、回复、usage、取舍原因及每张卡对应素材均保存。模型给出的理由是可检查说明，不是对其真实内部思考的访问，更不证明理由正确。

这些是本次真实表现，不是三包已经达到用户满意度的结论。

## 4. 三类主线问题，外加一个工程问题

### A. 最终卡片没有真正一起比较

**真实例子：包3的21、27、30。** 模型把园区标识、机构标识、办公楼都判为园区候选Chapter的同一故事。这个Chapter因容量落选后，三个片段又一起占满Aha。其排序理由明确是“在各自Chapter中的核心程度”；前12个候选因已被所选Chapter占用而退出，随后三个并没有再次作为一个组合比较。

缺口不是“建筑不精彩”，而是**属于哪里、单项排第几、放进最终组合还能增加什么，是三个不同问题。** 目前前两件较明确，第三件未可靠落实。同一落选经历可以贡献独立Aha，但不能默认其每个片段都值得独立占一张。

建议方向：在已有编辑环节中比较最终Chapter与Aha的整体组合，明确每张的额外价值与备选关系；不添加建筑黑名单、人物优先级、每场景固定名额，也不直接加“同章最多一个Aha”的硬规则。这是编辑任务设计，不是再叠一个API审核层。

包3“夜行还是洛阳占第四章”的选择也需要用户偏好验证。现有证据不能断言必须选洛阳或必须选夜行。

### B. 前面认出的内容，没有可靠交给最后精选

有两个不同但相关的实际环节：

- **输入遗漏：包2视频23。** 后续帧有人物笑脸，但S10只收到首帧道路，最后选了相近道路21、22。不能要求模型在没看到后续画面的情况下可靠比较它。
- **主线兑现：包3足球。** S07已把16号射门/扑救标为高潮，候选主线包含比赛到颁奖；S10却只留比分、奖杯、庆祝，并声称完整覆盖。不是上游完全没看懂，而是精选阶段改了重点却没有承认变化。

包1碑石13还有“先因属于章而退出Aha，后又被章精选省略”的去向。省略本身不一定错，关键是遗漏是否让一次原本值得保留的发现彻底消失。

建议方向：让S10获得能代表现有视频事实的证据，并把最后3–5件作为一个互补组合选择；主要内容被放弃时如实说明。不强制每个候选贡献都必须留下，不自动把章内落选图恢复成Aha，也不强制人物/动作每章各一个。

### C. 文案普遍不够聚焦，格式通过也不代表可用

- 7/7 Aha超过24字容忍线：41、51、36、40、42、42、43字。共同形态是“主体＋颜色/形状＋背景＋抽象氛围”，不是一个场景的特殊问题。
- 包2“驼铃似隐似现”没有相应声音或铃铛事实；包3上游“日出或日落”的不确定性，下游变成了确定的“夕照”。
- 包3足球中文正文混入 `podium`；包2鹿章仅因13字标题超上限，整段Writer正文也被换成“生活片段＋完整事实”。

建议把“选哪一个重点”和“用什么语气说”分清，允许自然氛围但不靠大量定语与无据具体细节制造情绪。标题格式错误对正文的影响范围另做小型工程修复。不重开已失败的反复API改写或只加严字数提示方案，不写词语黑名单。

### D. 排序完整性校验范围设得过严

包2只有两件的火锅组本来不能发布，模型也解释不成章；它没写进排序却导致**另外四个已完整排序的可发布Chapter整路退回旧方法**。

这是我新增交接设计中的问题，不是素材不够好。建议让必需排序范围与实际可参与选择的候选一致，保留原始漏项审计；如果真正可选候选缺失，再明确处理。只做引用/资格/范围层面的工程修复，不猜模型优先级、不新增重试。

## 5. 下一步怎么拆，避免再长时间钻细节

本轮完成后停在这里：保存全部真实结果，**不继续抽卡、不立即把V1.70升成Web默认**。

| 顺序 | 下一小步 | 交付与案例 | 明确不做 |
|---|---|---|---|
| 1 | 先收敛整日组合与Aha分工设计 | 用包3现有候选说明：哪些章占位后，三张Aha分别增加什么；原生独立提案和备选片段如何区别 | 不重开全架构，不把案例写成场景规则，不改S04/Writer |
| 2 | 做必要且小范围的交接实施 | 同时修包2不可发布组误触整路回退；保存实际生效/回退依据 | 不扩大为全面容错框架，不补猜编号 |
| 3 | 单独处理S10的代表证据与组合选择 | 用包2的23号视频、包3比赛组检查“看到了什么、最终保住什么” | 不规定人物必选，不删除低于三件的整章来掩盖问题 |
| 4 | 单独处理Writer的聚焦和兜底范围 | 三包现有文案作为评价清单，比较是否更自然、少罗列、无无据具体扩写 | 不因为一句不满意连发API重写 |
| 5 | 候选封存后再做完整真实验收 | 每次完整测试仍从素材标准化到最终预览跑所有环节，逐包反馈 | 不将只读回放或局部诊断说成全链质量通过 |

上述是建议，不是本轮已实施的修改。第一步先交付能讨论的短设计，涉及用户体验取舍时集中询问；基础归档和明确的工程检查不再逐条索取“同意”。

最终素材不可能全留，也没有必要全留。验收应问：**主要经历是否清楚？少数精选是否互补？Aha是否真的增加一点记忆价值？文案是否自然可信？** 数量、字符数、程序通过率只能辅助，不能替代这些问题。

## 6. 验证强度与后续真实用户数据

三包已经多轮参与开发，是回归素材，不是未见测试集；本轮也只有每包一次，不能估计稳定性或人群满意度。手机素材无可信时间/GPS，按一批当一天测试，不能据此验证真实穿戴日时间聚类或月成本。

未来新增真实素材时，评价要绑定具体对象：

- 整天：重要经历有无漏掉，是否整体值得回看。
- 某个Chapter：边界是否清楚，哪些素材重复、缺了哪件，是否仍至少三件。
- 某个Aha：单独是否值得留，与哪张已有卡重复，为什么。
- 某段文字：焦点、自然度、无据细节、是否过长。
- 批次上下文：用户类型、素材采集方式、可用时间信息、算法版本。

这些先作为带版本的评价记录积累，再归纳跨用户共性。保留独立用户/日期作未见验证；模型训练或微调要等重复、可归因的真实误差与人工标签足够后再判断。本轮未训练模型、未收集新的用户评分，不把助手审阅伪装为用户标签。
