# codex D1｜经历选择与 Chapter/Aha 分工草案

日期：2026-09-07。承接 V1.69 三包复盘。**设计草案，未实现、未冻结为产品规则。**

## 1. 这一小步要解决什么

目标不是多写几个标题，而是：主要经历能进入比较；独立的小发现有机会留下；最终图片与文案不偏离选定的内容。

位置：素材 → S04 识别事实 → **S07 提案、S08/S09 选组合、S10 精选** → S11 文案 → 预览。

本轮只设计粗体部分，不改代码、不调用 API、不切换 Web/App。44 个冻结源码/合同已重新核验，无漂移；V1.69 质量未接受的结论不变。Writer 错绑、视觉模型升级、文案长度和正式导出各自另做，不混在本步。

## 2. 先纠正一个方向：这些原则并不是代码里没写

现有提示已经要求“具体经历优先”“不是必须有起承转合”“同故事不重复”“相似素材不直接砍章”。S10 也已允许三到五件。因此不能把再写一遍这些话当作架构修复。

真正需要改变的是**选择的职责与结果交接**：目前结构模型提出候选，程序再用事件类别、稀少程度等代理分排序，精选模型又可能改变内容重心。每步看似合理，最终却不一定围绕同一段值得记住的经历。

另一个实际限制：本轮 S07 的图像输入为零，只读 S04 事实与辅助信息；S10 才再次看精选比较图。人看原图发现的联系，未必已写进 S07 的输入。本方案不声称只改分组提示就能修正上游看错或漏写的事实。

## 3. 建议的四步职责——不增加四次调用

以下是现有环节的工作分解，不是新增四层检查。

| 步骤 | 应做的判断 | 交给下一步什么 | 三包真实案例 |
|---|---|---|---|
| ① 找出可成立的经历和发现 | 哪些素材能一起表达一段具体活动或探索？剩余素材中是否还有未考虑的内容？ | 现有候选成员、事实引用、简短主线；不把目标三四章误当最多只能提出三四个候选 | 包3夜间建筑、人群、街边两人23–25应得到实际比较机会，而不只留下容易命名的地标 |
| ② 比较整日的取舍 | 哪组值得成章？哪些发现相对其他候选更值得留下？ | 可追查的相对优先级与选择理由；程序执行既有数量、素材底线和引用约束 | 包3单车/办公楼不应只因为对象稀少、合法事件代码和画质分就胜出；也不预定街边人物必胜 |
| ③ 明确相关卡片的分工 | Aha是另一件有意味的小事，还是章本身的核心或重复近景？ | 复用已有Chapter/Aha关系，明确各自内容；无关卡片不填满两两关系表 | 包1小狗同行不能换种文案再发；包2鹿同故事抑制已有效，应保留这个正向结果 |
| ④ 用精选素材兑现主线 | 去掉这张后，是否失去这段经历重要的一面？多加一张是否真有新增内容？ | 三到五件精选与实际被支持的主线，供Writer表达 | 包3足球三张全是赛果/庆祝，需要比较“加入比赛动作”的方案；不能用三个不同角色名就证明素材互补 |

第一步的“有机会比较”不等于必须入选，也不要求每件素材都写省略理由。只针对确有内容的剩余小组/发现做取舍，不输出冗长全素材检查表。

第二步的相对优先级是**待验证的模型编辑判断**，不是已训练好的个人兴趣分，更不是要求用户新填偏好问卷。模型给出理由也不是正确性的证明，仍要由真实素材和用户评价检验。

第三步不更改此前搁置的边界：关系不确定不能新加硬阻断；同一建筑、同一时间线不自动等于同故事，近景也不自动等于独立故事。

第四步不要求每章完整记录所有过程。例如庆祝本身可以是一章；问题是先确定重心，再据此选图，不能先选了三张庆祝图，事后才把“观赛经历”解释成“只看赛后”。真实动作不在S10首帧中的问题另做输入改进，不假装目前已经解决。

## 4. “值得记住”怎样判断，避免再造一套假兴趣分

建议围绕三个问题作相对比较，不把它们变成又一组固定权重：

- **这是什么具体的经历或发现？** 描述的是材料中实际存在的内容，不是只有“旅游、动物、建筑”类别名。
- **为什么值得在今天留下它？** 可以是动作、互动、独特细节、鲜明氛围或安静但有辨识度的画面；不要求惊险、新奇事件，也不强制必须有人。
- **它比已经留下的内容多了什么？** 与本日其他卡片共同看，而不是每张单独自评“很精彩”。

例：包2的室内夹肉画面虽不足三件成章，仍有具体动作可成为Aha；包3的单车不是天生不够格，但现有“扫码器、标签清晰”的描述尚未说明它相对其他候选的价值。

没有个人背景时，只能做共识性的编辑判断，不能臆测“这是用户最爱的单车”“这栋楼是用户的公司”。Manual来源可提供主动采集背景，但不因此免除去重或保证进入记忆卡片。

## 5. 接口保持简洁，别把设计变成更多字段

优先复用已有：成员与事实引用、thesis（这一章主要是什么）、reason（取舍说明）、aha_relations（章与Aha的分工）、精选排序。

本草案**不新增**对象数量上限、场景词表、情绪模板、兴趣标签类别或所有卡片两两评分矩阵。暂不增加每个候选一大段故事草稿，以免编辑说明被后续误作事实。

有一项真正的接口变化需要后续工程设计：模型的相对选择如何交给S09，而不是又被旧分数覆盖。可以用紧凑的候选顺序表达，但合法引用、三件底线、容量、重复提案处理不能因此失效。编码格式与失败行为未在本草案中冻结。

分工只从已有证据中分配，不负责创造新事实。S10若省略了支撑某个内容的素材，传给Writer的事实范围与内容重心要相应收窄；不是重新识别或再次生成。Writer的跨卡身份绑定修复仍为独立工作。

## 6. 首次实施只验证一个假设

**假设：让现有S07提出的编辑取舍被S09实际消费，比继续依赖类别/稀少度代理分，更能保留重要经历和独立Aha。**

这是S07→S09的一个职责交接改动，不在同一轮换视觉模型、重写Writer或改S10视频选帧。S10的主线兑现作为最终检查项；若它仍导致内容丢失，记录下来，在下一轮单独处理，不能把上下游同时改后宣称找到单一原因。

实施前需核清现有候选兼容与本地选择的影响，不把以上设计直接粘贴成更长Prompt。若只是增加要求而没有改变结果如何被使用，就不值得发布新版本。

实现后冻结一个研究候选，三包各一次完整重新处理，不复用旧事实、不挑好结果重跑。阶段回放可检查身份交接，但不能替代全链质量测试。

验收看具体结果，而不是是否达到数量或“模型理由写得好”：

- 包3夜间街头23–25是否得到有依据的取舍，山顶48是否不再被无依据归进另一组。
- 包1小狗同故事是否不再双发；包2室内用餐/夜市分开及独立夹肉Aha是否被保住。
- Aha排序是否更有可感知的理由，且不把普通生活发现一并筛空。
- 新增错误、旧正向结果退化、未确定关系、耗时与费用全部同时报告。

这三包仍是开发回归素材，不能证明新用户泛化或用户满意度。编号只定位真实样本，不进入运行时特例。

## 7. 体验判断与后续反馈

不重问已定的最低三件、目标三四章、同故事不重复、无时间不能编造先后等原则。

当前有主观分歧的案例，先留作用户评价，**不自动转成额外拦截规则**：

- 包3白马寺与夜街：同城文化线索是否足以让用户觉得是一章，要看具体探索关联；暂按已有“宽泛主题不足以合章”原则，不新规定所有跨地点必须拆开。
- 包3观赛：比分/奖杯/纸屑与比赛动作如何取舍，允许用户偏好不同，不预定体育素材模板。
- 包3金殿：章内已有山顶建筑和挂锁，近景另见殿门与神像；它是独立细节发现，还是更适合成为章内精选？当前倾向先作章内补充候选，但这只是对本组实际图的编辑建议，不是“近景不能做Aha”。
