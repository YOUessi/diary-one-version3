# codex V1.45 — 共性机制核查与优先改进项

2026-09-03。状态：ANALYSIS_COMPLETE_PROPOSAL_NOT_FROZEN_OR_IMPLEMENTED。

## 结论先读

优先建议：让分组、素材精选和文案共享一份精简的“内容说明”，保留共同主题、每份素材的内容贡献、对应事实及实际展示范围。模型据此决定重点和必要补充，不按场景词表写文案，也不规定必须描述几个物体。

这是修补已有步骤的信息衔接，不是重新设计整条算法，也不是新增一个 Agent 或模型调用。它尚未实现、尚未证明能改善真实质量。本轮只核查代码、既有记录并存档，无 API 调用、运行代码或 Web 改动。

用户已否定继续追查单张餐车图作为下一阶段主线。本记录取代 V1.44 的该项后续建议；V1.43/V1.44 实际输出、费用和失败记录保留，不改写历史。个案只作为发现共性问题的证据，不成为不断加规则的依据。

## 1. 已有设计与实际传递

| 环节 | 当前已经做到 | 核查到的差距/边界 |
| --- | --- | --- |

| S11 文案 | 当前运行代码传递事实、精选素材、完整主题/Beat 结构；要求自然、简洁，不列举全部细节 | 传入较大的组织/审计结构，不是围绕当前展示范围的精简内容说明；S10 选择理由没有进入 Writer，主题/Beat 结构也未随展示子集整理。V1.43/V1.44 精简实验则走向另一端，连主题、素材贡献和 Aha 的内容职责一起移除 |

这里有三种不同性质的结论：**代码确认的信息缺口**、**既有真实输出的问题**、**尚待验证的原因假设**。不能把“少了内容说明”直接宣布成所有质量问题的根因；V1.40 保留了完整组织信息，文案也没有因此达标。

### 真实记录中的结构核对

没有重看单图或重跑模型，仅核对 V1.40 与 V1.43 存档的数据结构：

- 三个 Chapter 原本均有主题，分别有 4/4/5 条非空素材贡献说明。
- 三个 Aha 原本均有内容职责说明。
- V1.43 精简后，六条事实原文与编号保留，但上述主题、贡献和职责全部不再发送；V1.44 复用了同一份精简输入。
- 因而“事实文字没变”不等于“可用于选择重点的上下文没变”。这一点可由存档直接确认，不依赖猜测模型内部如何思考。

## 2. 优先机制：精简但保留内容关系

“内容说明”回答三个问题，优先复用当前模型已经输出的信息，具体字段名和接口版本留到实施设计时确定：

1. **这段记忆围绕什么？** 保留分组阶段的共同主题；Aha 保留自身内容职责。明确它是组织提示，不把其中未经事实支持的地点、身份、意图等升级成证据。
2. **当前选中的素材分别增加什么？** 保留素材与对应事实的归属，以及已有贡献说明。精选后整理到实际展示范围，不把被省略素材的内容当作当前正文依据，也不把封面排名等同文字重点排名。
3. **文字应从哪里取舍？** 按主题贴合程度、具体特点、相对其他内容的新增意义，选择核心和必要补充。由模型结合这组真实内容作相对判断；不机械排序名词、不设兴趣分数权重、不要求凑满两三个或三四个细节。

S10 用同一份主题/贡献说明帮助比较“视觉差异是否服务于这段记忆”；S11 在精选结果上自然表达。程序负责 ID/来源映射、展示范围和确定性格式，不新增一个基于关键词的语义裁判。

**机制说明例子，不是新测试样本或规则：** 用户提出的长时间古建筑游览，可以共享“漫步/欣赏建筑”的主题；不同外观、内部细节各自是否有增量，要结合实际素材判断。因此可以保留多个有价值的建筑外观，不因为都叫“建筑”就去重，也不因为出现“木雕”就自动优先。文案只需概括核心体验及必要细节，不逐张报物体。

如果真实素材换成人物互动、运动或日常活动，判断仍是主题、具体内容和增量，不切换到“家庭必写动作”“运动必写热血”等模板。本轮没有生成这些场景的虚拟错误，也没有为它们指定标准答案。

### 这一步明确不做什么

- 不新增 `focus_reviews`、长篇理由或额外写前审查调用；V1.42 的复合输出失败不能被忽略。
- 不重新分组、不更改精选的三项底线、不修改 Chapter/Aha 配额，不因说明缺失而新增整章阻断。
- 不把模型的主题说明当事实，不自动修正源事实；未知时间仍未知，不把导入顺序当真实先后。
- 不禁止所有氛围词，也不新增猫狗、食物、建筑等专属许可或禁词。
- 不将“精简内容说明”冒称为已经实现 V1.22 的完整 Content Plan。只继承其内容取舍与表达分工；V1.33 已撤销的历史具体词表、猫狗窄许可不恢复。
- 不让 Writer 通过换词制造 Aha 的独立价值。入选是否有意义和文案是否好读分开评价。

## 3. 为什么先做这里，而不是一次重改所有环节

这项优先级是工程与验证顺序的判断，不是已经证明的最大质量收益：已有主题和贡献可复用，能跨素材检验，预期不增加模型调用次数，也不必现在就凭感觉重调价值权重。相比 V1.43 的平铺事实，恢复必要上下文可能增加输入 token；是否比原大包更省、是否值得成本，需要实测，不能预先承诺。

其他共性问题保留为独立待验证项：

| 问题 | 当前证据 | 后续处理边界 |
| --- | --- | --- |
| Aha 是否过度依赖前面的事件标签 | `_build_aha_candidates` 对模型提案也检查既有事件类型和显著程度 | 需要多包真实“值得 Aha 但没入选”的标注，判断漏在识别、提案还是筛选；本轮不放宽门槛、不凑数量 |
| Chapter/Aha 排序是否符合人的记忆价值 | 当前公式/代理量可读，尚无本轮跨用户评分证据 | 先积累真实偏好比较，再调整；不把画质、少见标签或数量直接称为兴趣 |
| Chapter 与 Aha 的故事独立性 | 当前程序只检查模型分配为高潮/结果的事实复用等有限情况 | 未命中冲突不等于独立性已通过；保留单独评价，不靠 Writer 解决 |
| 重要动作是否在理解阶段被遗漏 | 既有 V1.41 有真实输入差异记录，不能外推所有场景 | 用新增真实样本评价重要信息保留；不因一个例子新增专门动作检测器 |
| 长引用编号复制错误 | V1.44 的两条真实输出抄错编号 | 可后续采用程序管理的短别名；这是引用可靠性，不是文案质量修复。本轮不顺便实施 |

例如，一份日常素材没有产生 Aha，应该根据用户实际标出的精彩处定位损失环节，而不是先假定要降低所有门槛；如果用户也没有选出值得保留的瞬间，则不能靠文案捏造惊喜。此例说明评价方法，不是新增最低数量规则。

## 4. 跨素材验证设计

本节是后续实验方案，不是本轮已执行结果或新增调用授权。

1. **先验交接，不测“文笔”。** 用既有真实记录离线检查：事实不变、主题仍标为组织提示、素材贡献可追溯、当前展示范围正确、Aha 职责没有丢失。例：从四项精选为三项后，正文依据只能来自当前允许的事实；原始第四项仍在账本里。只检查结构，不编造语义反例；这不是筛选哪些素材包值得运行的 Gate0，不跳过后续完整流程。
2. **固定方案，再跨现有三个包对照。** 基线与候选固定同一模型、素材和其他策略，比较的变量是内容交接；不把模型、筛选门槛和写作规则同时调。需要完整测试时，每包两版都运行完整流程，逐步记录耗时/token/费用，不能用 Writer 回放冒充新版本全链路。全流程模型输出仍可能有采样波动，一对结果不能排除随机差异；如需离线隔离某个交接效果，应单独标为局部实验。预算需先列清，本轮不自动启动这六次完整运行。
3. **结果与素材一起评价。** 按具体 Chapter/Aha、精选素材和句子，记录“更好/相当/更差/无法判断”及理由；同时看分组清晰度、精选代表性/重复、Aha 保留价值、文案自然度/重点/可信度及整日遗漏。例：文字更顺但图片仍混乱，只能算表达变化，不能算整条记忆变好。
4. **区分开发集与真正未见样本。** 素材包 2 已反复用于调整；1、2、3 都曾在项目中开放使用，未核验完整使用历史前不能称为干净的保留测试集。三包先作为开发/回归覆盖，不按卡片数冒充独立用户数。未来方案固定后，新增未参与调整的用户素材再检验迁移，失败后若用于调参，就不再把它当未见验证。

评价以人对真实内容的判断为主，不用“与人工范文逐字一致”作标准，也不只统计 JSON/引用通过率。成本与时延另列；一次改善不宣称统计显著或生产可用。没有明确跨包收益时，保留未接受状态，不无限追加提示词和调用。
