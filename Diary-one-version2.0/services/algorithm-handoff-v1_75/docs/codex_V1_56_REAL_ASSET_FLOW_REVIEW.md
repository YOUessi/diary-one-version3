## 1. 结论与本阶段边界

现在不应继续围绕某一句 Writer 文案细磨。此次定位到两处可复现的程序性内容损失，以及一处已知的交付阻断：

1. **Chapter 的沿河素材并非完全没被模型选中。** S10 模型选择了 M04、M08、M11，但程序要求返回全部 9 项的排名，将有效的 3 项精选整组弃用，改取画质分前三，M11 因此消失。

这些问题不需要增加“古镇必须有河道”“石刻与倒影永不重复”等场景专属规则。下一步先做一个小范围的 S10 接收合同修复；其他问题独立推进，不在本阶段扩成全套重构。

## 3. 沿河画面究竟在哪一步消失

S04 保存了 M11、M14、M19 的事实。分组模型把三者都放入 C3。S10 请求包含 C3 全部 9 项的预览帧、事实和内容贡献提示；不存在这些沿河素材未送达 S10 的问题。

| 环节 | 实际结果 |
| --- | --- |
| S10 模型收到 | M04、M08、M10、M11、M13、M14、M16、M17、M19 |
| 模型返回 | 排名 M04、M08、M11；展示数量 3；明确说明 M11 小船/倒影的贡献 |
| 引用检查事实 | 返回的 3 个编号均真实属于候选，互不重复，数量与 display_count 一致 |
| 程序额外要求 | 排名长度必须等于输入成员数，即必须排完 9 项 |
| 程序实际执行 | 整组弃用模型选择，按 quality_score 降序、同分按 ID 排序取 3 个 |
| 最终精选 | M17、M08、M10；全部沿河素材不在展示集 |
| Writer 输入 | C3 仅收到最终三素材的 7 条事实；不含 M11/M14/M19 的事实 |

原 prompt 的确要求了完整排名，因此不能说模型完全遵守了请求；但随请求保存的 Schema 允许排名数组最少 3 项，运行时却要求 9 项。产品需要的是 3–5 个精选素材，丢弃已有有效精选并非这一产品要求所必需。

当前 `codex_chapter_media.choose_display` 回放原始 `codex_010_response.json`，仍准确复现 M17/M08/M10 和 `MODEL_SELECTION_REFERENCES_OR_COUNT_INVALID`。因此不是只存在于旧文档中的疑点。

**下一小步建议：** 让“有效精选集合”和“全部候选排名”职责分开；合法、唯一、属于本 Chapter、满足 3–5 数量的精选不应因为未列完落选项而全部损失。继续保留成员归属与引用校验；不补写故事、不用相似词规则、不重发 API 抽卡。需要核对后续排名字段消费者，不能伪造未返回的完整模型排名。先以这份真实回复作离线回归，随后再通过完整真实流程验收质量。

## 4. Aha 的两层损失，不要混为一谈

### 4.1 候选选择阶段：错误的“同一事件”推断

M13 与 M14 均被 S04 标为 `DISCOVERY`、`HISTORIC_TOWN_WALK`，共享 `HISTORIC_ARCHITECTURE` / `STREET_SCENE` 大类；素材序号相差 1。

但细节标签分别是石刻/书法/绿植，与河道/桥/白墙/倒影，交集为空。已查看实际抽帧，前者为林木石阶旁的石刻，后者为沿河屋舍及水面倒影。

`x02._aha_pair_conflict` 仍因“大类相交 + 事件类别相同 + 同一活动类别 + 导入间隔不大于 2”返回 `SAME_LOCAL_EVENT_SIGNATURE`。按真实候选字段重新回放，结果与历史账本一致：M14 被 M13 抑制。

这证明的是当前去重依据不足，不证明 M14 一定应成为最终 Aha，也不证明删除此规则后最终会多一个 Aha；还需经过其他选择、故事独立性和展示环节。一般化修正方向是：导入邻近和大类相同不能独立证明同一事件，不应把导入编号冒充可靠时间。

另有更早的候选入口问题：Structure 模型提出 6 个 Aha，3 个因初始事件类别不满足门槛被拒绝，另 3 个因内部说明 narrative_duty 超过 120 字符被拒绝。后来由初始事件标签生成的候选才有 3 个进入精选。其中 M11 的沿河倒影提名受初始 NONE 类别限制。部分模型提案本身含猜测，不能把这 6 个全部直接放行；应后续独立核查初始标签是否承担了过强的否决权，而不是增加特定景物的例外名单。

### 4.2 已经选中之后：文案失败导致全部不可见

M03、M09、M13 在 S09 均已选中，S10 均有媒体；最终账本均为 `COPY_BLOCKED / DIAGNOSTIC_ONLY`。

- Writer 首次三条正文分别为 38、41、41 个可见字符，被当时 20 字硬门槛拒绝。
- 第二次 API 返回同一候选在不同数组重复出现，三项均被记录为 `WRITER_ITEM_DUPLICATED`。
- 审计中的 attempt 3 是本地回退，不是第三次 API；回退失败，最终 Aha 数量为 0。

当前主代码仍有 `AHA_MOMENT_LINE_VISIBLE_MAX = 20`。用户已接受的“20 字目标、适度容差”尚不能等同于主链路已完成修改。应独立解决返回结构、长度策略和失败状态；不恢复反复调用 API 重写，不把 24 字另立为新的绝对淘汰线，也不能为了有结果就接受不可信文案。

## 5. 聚类问题与本轮不作出的结论

C2 中，祈福牌素材 M03 在 S04 被标为 `NATURE_TRAIL`；分组模型随后以相同场景类别、步行活动与共同意象，和林间 M09/M15 串成一段“入口—行走—收束”。实际看图支持其视觉重点不同，但没有可靠时间或路线信息，不能仅凭本次检查断言它们绝不可能属于同一次游览。

需后续解决的共性问题是：**同一种标签或能写成一段话，不等于已经证明是连贯的一段体验。** 当前分组 PASS 标记只验证结构和引用，不证明语义聚类质量。不要添加“祈福不能和树林同章”的硬规则。

此次也没有证明模型最初选出的 M04/M08/M11 已是最佳精选、3 个已选 Aha 都有足够惊喜感，或原有文案事实全部正确。这些仍需整组画面和用户评价。
