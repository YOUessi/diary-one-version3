# codex D4｜Aha 集合编辑器设计 v0.1

日期：2026-09-11。状态：**两项产品边界已确认；已在 V1.73 独立研究入口实现，等待冻结与真实素材验证。**

承接 V1.72.1 素材包 1 的真实结果。本设计只处理一个问题：如何从一组已经有事实、原子 Moment 和焦点帧的 Aha 候选中，选出一组真正值得单独回看、彼此不重复的 Aha。它不重新识别图片，不改 Chapter 聚类，不改 Writer，不切换 Web/App，也不增加场景特例。

## 1. 结论先行

建议把当前一次 S07 大任务拆成两个语义职责：

1. **S07 负责发现：** 形成 Chapter 方案，并提出一个有界的 Aha 候选短名单；不再同时决定最终 Aha 集合和全部逐对关系。
2. **S09-A 负责编辑：** 用一次独立、纯文字的模型调用，逐项比较候选的独立回看价值、与 Chapter 的分工、Aha 之间的体验重复，最终选出 0–3 个。
3. **S09-B 负责执行：** 程序只核对编号、事实、数量、逐对关系和精确重复；不理解场景、不打兴趣分、不补位、不重试。

S08 已经在冻结流程中用于 Targeted Enrichment（定向补证），所以本设计不占用或改名 S08。新增职责属于 S09 的“最终集合选择”内部：`S09-A Aha Set Editor → S09-B Deterministic Validator/Executor`。

这不是再加一层审核，而是把原本挤在 S07 里、且在真实运行中没有被认真完成的最终编辑工作独立出来。

## 2. 为什么现有结构会失败

V1.72.1 的 S07 一次要完成：

- 从 20 个有据观察中组织 Chapter；
- 提出并选定 Aha；
- 为每个 Aha 锁定一条事实和一个焦点帧；
- 填写 9 条 Chapter/Aha 关系；
- 填写 3 条 Aha/Aha 关系；
- 给出整日选择理由。

真实结果的字段全部齐全，但三条 Aha 都变成“看到一个不同招牌”。三条 Aha/Aha 理由分别使用“不同食物”“不同摊位”“摊位和茶店不同”证明故事不同。模型完成了对象分类，却没有完成用户回看体验的比较。

因此当前缺陷不是少一句 Prompt，也不是视觉模型分不清对象，而是**候选发现与最终集合编辑挤在一个高负担任务里**。继续追加“不要只看对象”“招牌不算 Aha”等文字，既不能保证生效，也容易沉淀成错误的场景规则。

## 3. 新的全链位置

```text
S04 视觉事实
  ↓
S07 Chapter 方案 + Aha 候选短名单
  ↓
S09-A Aha Set Editor（新增；一次纯文字模型调用）
  ↓
S09-B 引用、关系、数量与重复的确定性校验
  ↓
S10 最终媒体选择
  ↓
S11 Writer
```

### 3.1 S07：只做发现，不再做最终 Aha 选单

S07 继续读取全部可用事实，并继续负责 Chapter 分组与 Chapter 推荐。Aha 部分改为提出**最多 8 个候选**；素材稀少时可以少于 8 个，禁止为了填满短名单而制造候选。

每个候选仍必须满足 V1.72.1 已验证的原子合同：

- 来自一个 observation；
- 只引用一条事实；
- 锁定该事实中的一个焦点帧；
- 有一个简短 `moment_focus`；
- 不凭标签、事件类别或画质分自动生成。

S07 不再提交最终 `aha_selections`，也不再填写最终 Chapter/Aha 与 Aha/Aha 关系矩阵。最终关系交给负担更小的 S09-A。

**为什么是最多 8 个：** 最终上限是 3 个，6–8 个候选能提供约两倍以上比较空间；同时避免把 20–55 个全部事实再次送进编辑模型。8 是首轮工程上限，不是“每天只能有 8 个精彩瞬间”的产品定义，必须由真实三包结果验证是否够用。

### 3.2 S09-A：独立编辑整组 Aha

输入仅包含：

- S07 已推荐 Chapter 的内部主题、成员事实和事实编号；
- 最多 8 个 Aha 候选的一条事实、焦点帧编号、`moment_focus` 与证据限制；
- 本批记录背景及其不确定性。

明确不输入：

- 原图或原视频；
- GPS、伪造的时间顺序或导入顺序故事；
- motif、事件类别、对象稀少度、画质分等代理排名；
- 用户并未提供的个人历史或兴趣结论。

这个模型不重新看图、不改写事实、不创造候选、不写最终文案。它只回答：**在这些已存在的候选里，哪几个组合最值得作为独立 Aha 留下？**

### 3.3 S09-B：程序只验证，不代替编辑

程序检查：

- 候选编号、observation、fact、focus frame 是否完全存在且一致；
- 最终数量是否在产品上限内；
- 每个最终 Chapter/Aha、Aha/Aha 组合是否有且只有一条关系；
- 同一 observation、同一事实、同一源素材的精确重复；
- 被选项是否都有完整的编辑结论。

程序不检查“烤饼是否比茶店更精彩”，也不通过关键词判断“招牌不是 Aha”。语义正确性仍由模型提出、真实素材人工评价验证。

## 4. 编辑器的判断顺序

不用固定权重和总分。一次模型回复内按以下顺序完成，避免最后用三个最高分机械 Top-K。

### 4.1 先看单个候选：它是否能单独回看

每个候选只能得到一种内部状态：

- `STANDALONE`：事实中有一个具体 Moment，脱离 Chapter 后仍有独立回看意义；
- `CHAPTER_SUPPORT`：素材有价值，但主要用于补充某个 Chapter，不值得另发一张卡；
- `UNRESOLVED`：现有事实不足以判断，不假装有价值或无价值。

判断围绕三个问题：

1. 用户回看这张卡时，能明确回到哪个具体画面或小经历？
2. 它是在增加一个 Moment，还是只提供地点、名称、分类或背景说明？
3. 它是否只是已选 Chapter 核心故事的近景、换角度或换句话说？

名称、建筑、静态景物都不被预先排除。一个对象的身份本身可以是有价值的发现，但模型必须说明它为什么能独立回看，不能只写“它和另一个对象名字不同”。

### 4.2 再看 Aha/Aha：比较体验职责，不比较名词

继续复用三种关系，不新增复杂分类：

- `SAME_STORY`：用户回看时承担相同体验职责，即使对象名、店名、角度或地点细节不同；
- `DISTINCT_STORY`：各自带来有证据支持的不同动作、互动、发现、变化或状态，能说明第二张新增了什么回看体验；
- `UNRESOLVED`：事实不足以确认。

模型需要做一个通用的“名词替换检查”：如果去掉具体店名、物种名或物品名，两张卡仍只是在表达同一种体验，就不能仅凭名词不同判为 `DISTINCT_STORY`。这只是思考方法，不是硬编码拦截；当对象身份本身就是有意义的发现时，仍可以保留，但必须说明其独立价值。

### 4.3 最后选集合：先保证增量价值，再考虑整体丰富度

最终集合按以下优先顺序编辑：

1. 每个候选本身能成立；
2. 不重复已选 Chapter 的核心故事；
3. 不重复已选 Aha 的体验职责；
4. 在都成立的候选中，优先留下能让整批记录更丰富的组合。

“整体丰富度”只作相近候选的取舍，不设旅游、家庭、运动、宠物等配额，也不为了题材多样而留下较弱卡片。

## 5. 最小输出合同

建议 S09-A 只输出四类信息：

```json
{
  "candidate_reviews": [
    {
      "candidate_id": "...",
      "status": "STANDALONE | CHAPTER_SUPPORT | UNRESOLVED",
      "reason": "基于所引事实的简短编辑理由"
    }
  ],
  "selected_aha_ids": ["..."],
  "chapter_aha_relations": ["现有三状态、事实引用与理由"],
  "aha_aha_relations": ["现有三状态、事实引用与理由"],
  "set_reason": "为什么这一组比其他组合更适合回看"
}
```

不新增数值兴趣分、对象数量、场景类别、情绪模板或长篇故事草稿。`reason` 是可检查的编辑说明，不是新事实，也不直接展示给用户或作为 Writer 的事实来源。

## 6. 失败与不确定性

- S09-A 调用失败或回复整体无法解析：Chapter 路径继续，Aha 路径标记 `AHA_SET_EDITOR_UNAVAILABLE`；不回退到 S07 顺序，不自动补卡，不再调用一次抽卡。
- 某个被选 Aha 的引用或自身 review 无效：只拒绝该 Aha，有效兄弟项可继续。
- 一个候选 review 缺失但它未被选择：记录 `PARTIAL_CANDIDATE_REVIEW`，不得声称整组比较完整；不因此删除已经有完整关系的有效 Aha。
- 最终两张 Aha 的关系为 `SAME_STORY` 或 `UNRESOLVED`：不能同时发布，保留编辑器排在前面的一个，另一项留在候选账本，不物理删除素材。
- 少于目标数：不从落选 Chapter 片段、事件标签或画质排名自动补位。

以上失败处理保持“单次调用、局部失效可追查”的原则。研究阶段会分别统计技术失败和模型主动少选，不能把二者都写成“当天没有精彩内容”。

## 7. 用 V1.72.1 真实三条 Aha 演示

以下只演示编辑方法，不把“招牌、茶店、烤饼”写进运行规则。

| 现有候选 | 事实能支持什么 | 新编辑器可能怎样判断 | 原因 |
|---|---|---|---|
| 臭豆腐小摊 | 牌坊旁有一处写着“臭豆腐”的小摊 | `STANDALONE` 或边界候选 | 画面具体，但若与另一张都只表达“看见当地食品招牌”，体验职责可能重复 |
| 衢州烤饼摊 | 食品制作台、工作人员操作、摊前人员、招牌与甜筒 | 优先 `STANDALONE` | 除名称外还有实际摊位现场；当前 Writer 把它缩成招牌，是后续表达问题，不应反向否定候选事实 |
| 洪明茶门面 | 一处带招牌、灯笼与陈设的店铺门面 | 倾向 `CHAPTER_SUPPORT` | 画面成立，但现有事实尚未证明它比普通街巷门面多出独立回看价值；标题还存在 OCR 扩写风险 |

如果新编辑器只收到这三个候选，较严谨的结果可能只有烤饼摊一个，臭豆腐摊是否共存取决于它能否建立不同的回看职责，茶店不应为了凑三张自动进入。

这也说明为什么 S07 必须提供更宽的短名单：最终需要 2–3 个 Aha 时，编辑器要有机会比较石碑、人物互动、局部发现等其他真实候选，而不是在三个同类候选中强行选满。新完整运行前不预定具体哪一项必然入选。

## 8. 数量边界：真正需要产品确认的地方

我的建议是把所有记录统一为：

- 最终范围 `0–3 Aha`；
- 有充分候选时主动以 `2–3` 为目标；
- 只有一个成立时允许发布 1 个；
- 0 个只用于确实没有成立候选或 Aha 技术路径失败，并必须留下原因；不能因为素材少、没有 Chapter 或属于普通生活就直接归零。

这会改变现有“有 Chapter 最多 3、无 Chapter 最多 1”的旧研究限制。理由是：Chapter 需要至少三件素材，Aha 只需要一个原子 Moment；素材少到不足以成章，并不代表只能有一个值得回看的瞬间。

同一主题下允许多个 Aha，但必须有不同回看职责。两种不同商品名称不自动等于两个 Aha；同一主题中的两个不同动作、互动或发现也不应因为题材相似被一刀切。

## 9. 成本和效率预估

新增一次纯文字 Plus 调用，不发送图片，不重复 S04 识别。按仓库 2026-09-07 的历史北京公开价快照（输入每百万 Token ¥2、输出 ¥8）粗估：

- 约 4,000–8,000 输入 Token；
- 约 1,000–2,000 输出 Token；
- 单次约 ¥0.016–¥0.032。

这是设计估算，不是当前账单或真实测量。S07 同时删除最终 12 条关系及整组选单输出，能抵消一部分输出 Token；但因为候选短名单会变宽，不能在实测前宣称总时长或总 Token 一定下降。预计增加一次 10–30 秒级文字模型等待，实际必须从完整运行日志记录。

## 10. 实施与真实验证顺序

两项产品边界已经确认：所有记录统一允许 0–3 个 Aha，有充分候选时主动争取 2–3 个；同一主题的 Aha 可以共存，但必须承担不同的回看体验职责，不能只靠对象名称不同。实施仍按以下小步推进，不把多个问题混在一轮：

1. 新建 V1.73 独立研究入口，只接 S07 候选短名单、S09-A 编辑器和 S09-B 校验；不改 Web 默认。
2. 用匿名编号做协议测试，只验证缺字段、错引用、重复引用、关系不闭合和单次调用；不构造“模型把某动物认成另一动物”等虚拟语义错误。
3. 跑全量本地回归，冻结新候选，保留 V1.72.1 结果不改写。
4. 素材包 1 从标准化到 S12 完整重跑一次，不复用旧语义回复；重点比较 Aha 候选数、最终数、独立回看价值、体验重复、Chapter 重复、调用/时间/Token/费用。
5. 如果包 1 仍用实体名称冒充不同体验，停止并复盘，不连续抽卡；若主要缺陷改善，再以同一冻结版本跑包 2、包 3。

V1.72.1 已发现的“S10 后关系没有完整到达 Writer”是下一项独立交接修复。本设计只保证 S09 最终关系由专门编辑器产生，不借机扩大 Writer 事实输入，也不在同一轮修改文案逻辑。

## 11. 术语释义

- **候选短名单（shortlist）：** 还没有最终发布、但值得进入下一轮比较的一小组候选。
- **集合编辑器（set editor）：** 不重新识别内容，只从候选中选择一组彼此补充的最终结果。
- **独立回看价值（standalone revisit value）：** 脱离 Chapter 后，用户仍能理解为什么这个 Moment 值得单独看一眼。
- **体验职责（experience duty）：** 一张卡在回看时主要让用户记起什么；它不同于画面里出现了哪些对象。
- **原子 Moment：** 一条事实、一个焦点帧、一个核心动作/状态/发现，不把多个时刻拼成一张 Aha。
- **确定性校验：** 程序能客观检查的编号、数量、引用和结构，不包含“精彩不精彩”这类语义判断。
