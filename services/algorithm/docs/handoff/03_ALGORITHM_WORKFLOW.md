# 03｜算法全链路（通俗版）

## 目标

把一天的第一人称与主动拍摄素材，整理为通常 3–4 个高质量 Chapter（每个 3–5 个精选素材）和 0–3 个 Aha；有充分证据时积极寻找 2–3 个 Aha，但不自动补位或虚构。

## S00–S13

| 阶段 | 在做什么 | 关键原则 |
|---|---|---|
| S00 输入登记 | 建立当天素材清单和唯一 ID | 不丢素材，不伪造时间/GPS |
| S01 标准化 | 解码图片/视频，生成统一 Evidence | 失败要显式；不把失败当空日 |
| S02 上传路由 | 只准备模型真正需要的 Evidence | 原视频不直接交给模型；不补拉旧视频 |
| S03 Window/连续性 | 把相邻观察组织成可判断的小段 | Continuity 与 Boundary 双向证据并存 |
| S04 视觉理解 | 对小批 Evidence 生成 Observation 与 Fact | 事实与不确定性分开；不把例子写成场景规则 |

| S06 边界裁决 | 判断合并、切分、延后或丢弃 | 短插曲不一定切断 A–B–C 的主故事 |

| S09 全天编辑 | 选择 Chapter 与 Aha 集合 | Aha 搜索完整事实池；逐对检查故事关系 |

## 三个最重要的编辑判断

### 1. Chapter 是“经历”，不是相似图片堆

同一古镇可以按古镇漫步、文化细节、当地生活等不同故事职责切分；不能只靠“石板路相似”聚类，也不能因为都在古镇就全部混在一起。判断应综合场景、行为、人物互动、语义角色、连续性和边界证据。

### 2. Aha 是独立值得回看的小惊喜

Aha 可以发生在 Chapter 时间范围内，但必须承担不同故事。例如旅途中偶遇的独特甜品可以独立；生日 Chapter 中吹蜡烛通常仍是同一个核心故事。V1.75 要求 Chapter/Aha 与 Aha/Aha 关系矩阵闭合，缺失关系时保守拒绝。

### 3. Writer 负责表达，不负责改事实

Chapter 只需一到两句话，可以有克制的共识性氛围；不必列举所有对象。先按这段经历的核心兴趣排序，再选择少量事实表达。中文 Aha 以 20 个可见字符为目标、24 为当前上限；不能截断，也不通过二次模型重写抽卡。

## 禁止重新引入的做法

- “小狗、古镇、石板路”等案例专用运行规则；
- 未经真实素材发现就人为制造大量语义反例并固化 gate；
- 为满足数量自动补 Chapter/Aha；
- Writer 失败后反复调用模型直到抽到合格文案；
- 只因相似就保留或删除 Manual 素材；Manual 窗口与 Chapter/Aha 编辑是两条展示责任；
- 用标签或导入顺序强行覆盖故事成员关系。
