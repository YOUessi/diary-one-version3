# 02｜当前架构与量产边界

## 当前研究链路

```text
手机照片/视频
    │ 浏览器本地解码、抽帧、缩放
    ▼
Web Test Lab V1.63
    │ Bundle V04 + 标准化 Evidence；同步 HTTP
    ▼
Python X02 V04.1 研究 API
    ├─ S04：Qwen 视觉理解
    ├─ S05–S09：事实、结构、Chapter 与 Aha 编辑
    ├─ S10：Chapter 3–5 个展示素材
    └─ S11–S12：文案与最终校验
    │
    ├─ 本机 JSON Run Audit / Evaluation Sidecar
    └─ 结果返回 Web 展示与人工评价
```

## 算力由谁承担

| 位置 | 当前工作 | 主要成本/限制 |
|---|---|---|
| 浏览器/电脑 | 视频解码、抽帧、Evidence 标准化、页面渲染 | CPU、内存、浏览器兼容性 |
| Python API 主机 | 校验、批处理、规则执行、审计文件 | CPU、内存、同步请求时长 |
| Qwen API | 视觉理解、结构/编辑、Writer | Token/图像调用费用与网络时延 |
| 本地磁盘 | Run Audit 与人工评价 Sidecar | 无正式备份、权限或保留策略 |

## 当前数据去向

- 原始媒体：只在浏览器 Session 中处理；
- 标准化 Evidence：通过研究 API 发往视觉模型；
- 派生事实文字：可发往后续结构/Writer 模型；
- API Key：只在 API 主机的 Keychain 或环境变量；
- 结果与评价：当前写本机 JSON；
- 对象存储、正式数据库、删除周期：尚未实现。

## 推荐量产目标

```text
耳机端采集
  → 手机 App 本地同步/抽帧/轻量去重
  → 后台上传会话（无感、可续传）
  → 对象存储（原件/Evidence 分层）
  → 异步任务队列与编排器
  → 视觉/语言模型 API + 确定性规则服务
  → 结果数据库、版本/证据账本、人工评价库
  → App Chapter/Aha/Manual 窗口
  → 监控、费用告警、删除与审计
```

当前仓库只覆盖研究算法和本地测试台。耳机采集、正式 App、后台鉴权、异步队列、云存储、S13 HQ、监控与数据治理需要各自独立工程和接口合同。

## 不应直接沿用到量产的部分

- 同步等待 3–9 分钟的单个 HTTP 请求；
- 浏览器一次准备完整测试日 Evidence；
- `ThreadingHTTPServer`；
- 共享 Bearer Token；
- 本机 JSON 作为长期数据库；
- 将手机主动拍摄数据视为真实第一人称佩戴数据；
- 以导入顺序代替可靠时间/GPS。
