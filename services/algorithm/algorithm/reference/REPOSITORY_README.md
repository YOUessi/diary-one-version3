# Diary One Cloud Intelligence

Cloud-intelligence research harness and Production-shaped contract reference for the frozen Diary One pipeline through Canonical V1.25. E00 remains an engineering smoke baseline, X01 remains a historical one-call compatibility preview, X02 is the current staged real-media Web preview, the Production V1 reference validates the S00–S13 control flow, and Validation V01–V02 adds day-level design-gold contracts plus deterministic failure attribution. None of these claims cloud deployment, S13 completion, or real-media model accuracy.

The E00 smoke path is deliberately small and local:

`Source → logical 120s/9s assets → frames at 1.5/4.5/7.5s → embedding adapter → smoke moments → EVAL_V01 → transfer/cost trace → HTML report`

It does **not** materialize 9-second clips, call a paid model, enter a leaderboard, or implement Chapter, Aha, a production backend, or an agent framework.

That statement remains true for E00. The historical **X01 Diary Research Preview** exercises a one-call editorial bridge. The current **X02 Staged Real-Media Preview** separates bounded perception batches, structure proposals, deterministic candidate/set/media gates, grounded Writer, and final validation while leaving S13 explicitly unexecuted. A separate **Production-shaped V1 reference** validates immutable S00–S10 handoffs, executes S11/S12/S13 control-plane contracts, and writes reference-only artifacts; it does not run real perception, Writer, HQ rendering, cloud storage, or published-head CAS.

## Run

Python 3.9+ and no third-party packages are required for the built-in deterministic fixture.

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
PYTHONPATH=src python3 -m diary_one_ci.cli smoke
```

The command prints the run directory. Open `report.html` inside it. Run artifacts are content-addressed and include `manifest.json`, hashes, logical assets, frames, embeddings, observations, moments, evaluation, transfer/cost trace, and report.

For a real video, install `ffprobe`/`ffmpeg` and pass:

```bash
PYTHONPATH=src python3 -m diary_one_ci.cli smoke --source /path/to/portrait-3x4.mp4
```

Real-video geometry must be portrait 3:4. The fixture path exists so E00 remains runnable in a clean environment without multimedia packages.

The full-flow reference uses a closed Canonical Concept Registry and a checked-in ancient-town fixture. It validates S00–S10 handoffs, executes S11 and S12, simulates only predeclared S13 route outcomes, and writes deterministic JSON artifacts.

```bash
PYTHONPATH=src python3 -m diary_one_ci.cli production-v1 validate \
  fixtures/production_v1/ancient_town_reference_day.json

PYTHONPATH=src python3 -m diary_one_ci.cli production-v1 run \
  fixtures/production_v1/ancient_town_reference_day.json \
  --artifacts artifacts
```

Successful output is explicitly marked `REFERENCE_VALIDATED_NOT_CLOUD_PRODUCTION`; reference receipts contain no media bytes and no real publication is performed.
The input and emitted artifact boundaries are documented by `contracts/production_pipeline_v1.schema.json` and `contracts/production_pipeline_v1.outputs.schema.json`.

It validates contracts and attribution only: all labels are design gold and are structurally barred from becoming real-media accuracy claims.

```bash
PYTHONPATH=src python3 -m diary_one_ci.cli validation-v01 validate \

PYTHONPATH=src python3 -m diary_one_ci.cli validation-v01 run \
```

The command writes a content-addressed suite snapshot and `validation_scorecard.json`. The scorecard keeps Blocking, Quality, and Review outcomes separate and deliberately contains no overall score.

RC13's historical `App Library Bundle V01` accepts arbitrary Photos-library photos and videos using its fixed three-slot representation. Historical X02 V03 additionally accepts the research-only `App Library Bundle V02`: one photo frame and duration-aware phone-video Windows. The historical X02 V03 route explicitly rejects Bundle V03 so its semantics cannot drift. None of these phone-test profiles supersedes the frozen Auto 9-second three-frame contract. Read the current [App Library Bundle V03 sequence-only contract](docs/app-library-bundle-v03.md); [App research export V01](docs/app-research-export-v01.md) remains the historical V01 export reference. ## X02 staged real-media preview

The zero-dependency research server keeps the model credential on the Mac; the Web test page never stores it and never uploads original Photos-library media. The executable module remains `x01_server` for backward compatibility, but `/health` identifies X02 as the default path and keeps X01 under `historicalX01`.

```bash
# On macOS, store the key in the login Keychain as:
#   service: DiaryOne DashScope API Key
#   account: the current macOS user
# DASHSCOPE_API_KEY remains available as a non-macOS/CI override.
export DIARY_ONE_X01_BEARER_TOKEN="paired-with-the-research-app-build"
PYTHONPATH=src python3 -m diary_one_ci.x01_server \
  --adapter qwen --host 192.168.12.156 --port 8787 \
  --tls-cert /secure/local/path/x01.crt \
  --tls-key /secure/local/path/x01.key
```

The default provider/model is Alibaba Cloud Model Studio with the reproducible `qwen3-vl-flash-2026-01-22` snapshot. Override it with `DIARY_ONE_X01_QWEN_MODEL`. The mainland OpenAI-compatible endpoint is used by default; `DIARY_ONE_X01_QWEN_BASE_URL` can override it for a workspace-specific endpoint. The adapter requests JSON Object mode, then applies Diary One's own strict contract and evidence-reference validation.

`--adapter openai` remains available only as an explicit cross-vendor frame challenger and reads `OPENAI_API_KEY` plus optional `DIARY_ONE_X01_OPENAI_MODEL`. `--adapter fixture` is contract-test-only. Every X02 result attributes model-call count, frame count, token use, pricing basis, and estimated USD cost to the exact stage call; historical X01 audits retain their native-currency pricing snapshot. Pricing values can be overridden through the documented `DIARY_ONE_X01_QWEN_*` or `DIARY_ONE_X01_OPENAI_*` environment variables without changing the run contract.

Non-loopback serving requires TLS and bearer authentication. Authenticated `GET /health` reports the active V04.1 result/pipeline handshake, Storyline V02 and Writer surface identities, semantic-contract hash, field-degradation contract, fresh-run mode, and phone-test Evidence profile. `POST /x02/v0.4.1/preview` accepts `bundle.json` plus each declared Evidence frame as multipart fields, supports up to 240 assets per local test day, and plans S04 calls with simultaneous limits of three assets, eighteen frames, and four MiB of normalized Evidence. HTTP 413 or explicit asset-local output failures may isolate by bisection; timeout/5xx may retry the unchanged root batch once; ordinary 4xx including 429, non-timeout transport failures, and unusable structured responses do not retry or split. A single asset over four MiB fails preflight without a provider call, and the whole V04.1 run has a 96-model-attempt circuit breaker. Unresolved perception assets make the run diagnostic and blocked rather than a false Empty Day. In App Library Bundle V02/V03 duration-window Evidence, photos expose one frame; videos expose 1/3, 2/4, 4/8, or 6/12 Window/frame plans at the 10/30/90-second boundaries.

Successful X02 runs are atomically archived without embedded images under `var/x02_runs/` (override with `DIARY_ONE_X02_RUN_AUDIT_DIR`); `POST /x02/v0.4.1/run-sidecar` records bounded client timing and revisioned Human Evaluation V02 feedback bound to a specific archived Run. V04.1 separates `semantic_day_state` from `delivery_state` and records every S09-selected memory's S10/S11/visibility outcome. Before return, the algorithm applies a fail-closed runtime audit of Bundle coverage, batching lineage, state combinations, Memory outcomes, and time truth. The committed JSON Schema remains a separate interchange boundary, and the Web performs its own Bundle/health-bound result checks; no one layer substitutes for the other two. Formal quality evaluations declare `FRESH_FULL_RUN` and `cross_run_semantic_cache_used=false`. Existing audits remain immutable evidence. `/x02/v0.3/*` is the historical V03 route; the mutable `/x02/v0.4/*` route is deliberately retired rather than silently aliasing V04.1. Historical `/x01/v0.1/*` routes and `var/x01_runs/` remain available for comparison. If the selected adapter has no model key the server returns `model_not_ready`; it never silently substitutes its contract-test fixture.
