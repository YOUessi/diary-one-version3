## 一、正确的分章依据：内容第一，时间辅助

时间可帮助判断活动是否持续、是否出现实质转场和同一地点是否只是重复视角，不能因为过了多少分钟或再次看到一个地标便拆Chapter。应同时检查实际主体/活动、经历独立性、足够的视觉证据及其持续性。

基于人工偏移80秒组九个Chapter的97张图片，并对各偏移组的真实来源画面抽样复核，修正参考为4–5个宏观Chapter：

|---|---|---|
| R1 | Sydney Opera House、Circular Quay、The Rocks海港与老街 | 歌剧院近景/远景、海港大桥、广场、市集 |
| R2 | Darling Harbour滨水和海事探索 | 步道、游轮、古帆船、码头、海事建筑 |
| R3 | CBD / Chinatown购物及历史建筑 | 商业市场、教堂、室内拱廊、街巷 |
| R4 | Hyde Park雕塑和开放绿地 | 纪念像、喷泉、历史建筑与公园 |
| R5 | Royal Botanic Gardens园林漫步 | 多肉、棕榈、花坛、池塘、小径 |

## 三、为什么视觉库有歌剧院，但最终很多章没有

完整Mac截图和V05 visual_fact_ledger证实各组歌剧院确实被原始JPEG拍到。R5_25中S04识别到内容后，S09候选池chapter_media_pool.py将已核验素材按导入顺序排序，再通过_spread平均挑选少量资产；真正的产品调用是max_per_chapter=5,max_total=32。

这是一种时间平均抽样，不是内容价值排序，也没有对独立景观/地标实施最低覆盖保护，结果是有明显Opera House的图片在到达S09B视觉选择器之前就被过滤。

已核实的输入到成品照片差异：

| 偏移 | 原始已验证的歌剧院实图 | 最后进入S09的早期候选 | 结果 |
|---:|---|---|---|
| 0s | 000013-f0、000025-f0的Opera正面和宽景 | 000001、000073 | Opera全部缺席；C01封面改为游轮与步道 |
| 10s | 000014-f0、000038-f0、000086-f0的Opera近景 | 000002、000050、000098 | 只有柱廊侧墙，虽然C01标题写Opera |
| 20s | 000039-f0、000087-f0 | 000003、000075 | 原画存在但歌剧院被过滤 |
| 60s | 000019-f0、000031-f0、000091-f0等 | 000007、000079 | C01实际变露天餐饮区 |
| 80s | 000021-f0、000093-f0 | 000009 | C01只保留渡轮，Opera被放到不必要的结尾独立章 |

直接视觉审查最终成品：有11个具有最终产出的偏移组（排除70秒失败），其中只有30/40/50/110秒四组在前10分钟的**已发布画面**中明显展示歌剧院主体。40/80/90/100秒组主要在最后片段出现歌剧院；60秒组只是别的章节背景中隐约出现，不等于代表图。

**因此不能将“原始无歌剧院”“没识别出歌剧院”“选图没展示歌剧院”“题目没写歌剧院”混为一谈。**

## 六、修复和验收优先级

第一批只改通用算法，不针对悉尼硬编码：

1. Episode先识别主题持续和真实变化，Chapter最后再将4–5个主要经历整合，不因歌剧院再次出现强制拆章；可信的2分钟原始采样时间是辅助条件，不能假装已验证EXIF。
2. 章节媒体候选先对Scenelet/Episode作显著主体覆盖保护，再进行时间分散和画质排序；R1的Opera必须有真正可见的候选，若输入中确实不存在则不能伪造。
3. 标题、封面、正文应由同一批真实Frame Fact支持，否则先局部扩大候选/修复Focus而不是仅补名称。
4. 对S07区间仅缺末尾index有界安全恢复；S12缺字段的NOT_EVALUATED重试或续审；100秒S15媒体对账缺引用时局部重选而非删整个植物园章。
5. 新验收同时报告输入可识别、候选可用、最终可见和正确章归属四层覆盖；考核12组鲁棒性，而非是否机械输出五章。
