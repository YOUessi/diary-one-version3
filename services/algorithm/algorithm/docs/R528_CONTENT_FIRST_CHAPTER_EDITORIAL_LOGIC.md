# Diary One R5_28：将可复现的内容编辑准则落实到云端 Chapter

2026-11-04 ｜ 仓库 YOUessi/diary-one-version3 ｜ 实验分支 feature/2026-10-30-chapter-v2-boundary

## 0. 最重要的角色边界

用户希望 ChatGPT 作为独立 LLM-as-a-Judge，在云端**真正生成并发布** Chapter 后逐张检查效果；不要为此在云端添加另一个打分模型。

本次改动**不新增云端 LLM-as-a-Judge**。这些方法是云端生成算法的编辑准则、候选动作、数据流和合同校验。下述步骤是可观察、可复现的编辑决策解释，而不是模型隐藏的逐token内部思维。模型需要把决定绑定真实 Episode/F/P ID 和图像证据；不允许自己写没有来源的事实或重返路线。

## 1. 好的 Chapter 是如何组织的？

如果给我一整天的第一人称视角视频，我的可解释编辑判断可以拆成七个步骤：

1. **识别真实生活内容。** 视频片尾推广、播放器提示不是人生经历；真实街头广告、博物馆海报、实际店铺则可能属于用户看到的内容。把是否属于用户的经历，与仅仅识别出了什么物体严格区分。
2. **完整查看原始经历。** 视觉事实按发生来源记录，提取具体建筑、作品、人物活动、商品、自然景观、运动过程。一个显著的作品可能只出现10秒，却比上百张普通道路更值得记住。
3. **从事实中构造较细的 Episode。** 例如“歌剧院观景”“市集工艺品”“海事博物馆”“CBD拱廊”“海德公园喷泉”“植物园花坛”，先不要把最终章数作为硬约束。Episode可以按观察顺序提名，Chapter不要求连续。
4. **根据内容关系组织 Chapter。** 能够讲述同一段完整体验的Episode融合，即使在非相邻视频片段；不同主题即使在相邻素材也不应硬拼。同一地点再次出现完全可以融合进以前的Chapter，重复出现绝不需要额外开章。
5. **全球编辑动作：合并 / 调整归属 / 保留 / 过滤。** 一章商铺与植物园混合，就检查其他相关经历可否合并释放展示名额，然后将购物与园林重新归属；不是仅将这章改个更宽泛的标题。无法证明两个主题相同，则不要自动融合。
6. **一边组织 Chapter 一边审查真实图片候选。** 封面要最能表达整章主线，组图补不同有意义的Episode；不能由普通木桌/墙面取代已经核验的地标/作品，更不能借用另一Chapter的图片。封面也不能因为它是第一张或最清楚而自然获胜。
7. **保留完整真实叙事与可见缺口。** 文案应描述多个图片已支持的关键Episode，而不是只说“石阶、乐手、军舰、仙人掌”。一个Episode如果无入选照片，明确标记未覆盖，不应为了凑文案编造。

**时间的角色只有三种**：可信的先后和持续、场景变化的辅助证据、帮助不同Episode展示成有意义的记忆顺序。禁止用“距上章N分钟”“用户又回到原地”作为硬拆分条件；导入顺序不等于可信设备时钟。

## 2. R5_28已写入的具体模块

### 2.1 source_content_gate.py (延续R5_27)

保守过滤明确来源视频推广片尾，不自动丢弃街头广告及单条字幕。原始JPEG、原始观察和排除证据保留，最终publication ledger标记NON_LIVED_SOURCE_CONTENT。

### 2.2 global_visual_memory.py (延续并使用全局记忆)

保留完整fact ID与frame ID审计、代表性记忆锚点、未经证实的跨时间主体候选。模型可把初段和尾段相同具体主体视作合并候选，但不能把文字相似当成已验证的实体身份。

### 2.3 chapter_editorial_decision_flow.py (新增)

根据已经图片核验的Episode卡片，输出带来源fact ID的编辑候选：

- MIXED_THEME_REVIEW：一章包含性质明显不同、且有持久视觉证据的活动。提醒重新分配，不机械分章。
- SAME_THEME_CROSS_CHAPTER_MERGE_REVIEW：不同章呈现相同具体主题的候选，允许跨时间融合。通用WALKING标签或时间靠近不构成证据。
- OUTLIER_EPISODE_REVIEW：只有该Episode在另一个**已经存在**的Chapter里有更强的具体主体证据，才提示移动。此前110秒歌剧院被错误移动到植物园，根因就是旧逻辑只看文字重合度不足。
- budgeted_edit_recipe：混杂章节已把1–5章预算用满时，找其它证据确有共同主题的章节提出**合并候选**，以释放一个位置让真正独立的Episode成章。没有可靠的同主题合并，返回NO_SAFE_THEMATIC_SIBLING_MERGE，而不是臆造。

这些只是**有证据的生成动作建议**，程序不自动变更Episode归属；现有S07U/V/W根据事实决定，结果再经过唯一归属与F ID来源验证。没有额外云端Judge评分。

### 2.4 chapter_theme_hierarchy.py (增强)

- Episode每段代表事实不再只是最多16个时间均匀抽样；加入完整全日记忆里已通过图片核验的高价值主体锚点。
- S07U显式收到Episode证据卡与内容编辑决策顺序；现有S07V仅在新归属未增加来源确证的冲突时应用。
- 修复过去“被认为词汇不相似的Episode应移出本章”的危险旧规则：迁移必须有其它Chapter更可靠的具体主体支持。来自末尾的Opera House视觉重现不会因为时间晚或文字短被推到植物园。
- S07W既看到真实混杂问题，也收到合法的跨章合并、错章Episode移动和预算内重新分配的候选layout。它可以拒绝不合理的候选，不强制合并。
- S07U有且只有“超过4条仍为本章已核验F ID的锚点”这一有限合同修复：按来源分散保留4条，原始模型结果和审计记录不变，不能掩盖其它JSON/身份错误。
- 编译器保证每个Episode恰好归属一个Chapter、每条事实不能移动到不属于自己的源帧、原始已核验事实不丢失。

### 2.5 chapter_media_episode_plan.py (新增)

S09B之前，给每个Chapter列出真实来自哪些Episode的P候选；再根据S09A逐帧独立支持事实把未核验候选剔除出可选集合。生成器一轮看图时就知道这一章有哪些不同经历可表现，而不是机械从8张候选中随便拿5张。选图之后记录：

- represented_episode_ids：至少有一张真正入选画面的Episode
- source_verified_candidates_unselected：有真实通过S09A的图片但未被选中的Episode
- episodes_without_any_approved_candidate：该Episode没有任何可用已核验真实图像

这套账本只是生成与恢复的依据，不是新增独立Judge。无法被图像支持的片段不允许被文案硬写出来。

### 2.6 chapter_story_outline.py (延续R5_27)

S11收到每个Episode被选中的实际帧和对应的可信事实，避免整个CBD最后只写纪念品，或整段植物园只写仙人掌。S12独立事实核验仍是原有安全门禁。

## 4. 成功与失败必须分开验收

代码合同通过，只能证明执行可行、不会随意借用事实。最终标准由ChatGPT在聊天中独立检查真实发布的result.json、全部主图/高光和正文，不把S07预检或S09候选当成成功的成品。

对同一Citywalk的多偏移至少检查40/110典型回归；之后需扩展购物、骑行、钓鱼、亲子等其它来源。不能把单个悉尼案例的高分当作跨用户泛化。

## 5. 禁止事项

- 不加入新的云端LLM-as-a-Judge。
- 不在代码中硬编码Sydney、Opera House、Chinatown等地名的分章特殊规则。
- 不按时间阈值或重复地点机械分章。
- 不伪造来源帧、时间、人物身份和用户动作。
- 不上传原始长视频和私有模型调用凭证。
- 不以预检或通过了单元测试冒充真正最终可发布Chapter。
