# Diary One R5_26：内容优先、跨时间主题融合与视觉候选保护

日期：2026-11-03。适用路径：V05 App Library长日程（32段或以上）。本说明明确代码原理与已经取得的实验范围，正式云端发布仍须通过完整S09/S12/S14验收。

## 上一版为什么出现问题

R5_25让S07X直接把一整天规划为最多五个连续的源索引段，迫使最后再次出现的同一地标进入另一个时间段，无法在单章内跨时间融合。S09旧媒体候选池把源资产依序排序、然后平均抽每章最多五张真实图片；即使S04已经辨认出特别的建筑、作品、动物和事件，最终可能仍然因为不在五个平均位置而无法进入最后VLM图像审查。

悉尼多组实测已经证明：0、20、60、80秒组都实际拍到并识别歌剧院，但清晰图片未进入最终图库。是内容候选筛选和后续发布造成的遗漏，不是模型不认识悉尼歌剧院。

## 新流程

### S07T：发现有意义的Episode，不决定最终章数

新增chapter_theme_hierarchy.py。按照全部素材的视觉观察提出最多18个细粒度、完整覆盖的临时Episode。区间严守来源索引，不把导入顺序当成可信相机时间。只有发生了内容或活动上的实质区别，才考虑独立经历；相同地点重现只保留暂时的观察线索，并非创建新Chapter的理由。JSON若漏尾素材或编号错误，申请一次受限修复，否则明确阻断。

### S07U：通过真实内容组合1–5个Chapter

模型读完Episode后，决定主题和各Episode归属。Episode即使不相邻，也可在同一个Chapter融合：例如首尾同一歌剧院地标可归同一海港Chapter，而不必在末尾再开一个歌剧院章。每个Episode恰好归属一次；每章选择1–4条真实经过视觉核验的事实作为重点图片锚点，程序严格检查ID和来源，不允许移动、编造或复制视觉事实。

### S07V/S07W：独立主题复核

另一次语义编辑判断是否把长期购物、独立自然公园或海事场景硬拼为无主线的大杂烩。S07W只在发现明确的语义主题冲突时尝试受限重组，非法结果或无法改善的结果被拒绝，保留已经有效的模型方案。目标并非强行5章，也不是把所有无关内容凭时间合在一起。语义判断仍有误差，需要用不同真实行程评测。

### S09：先保护高价值视觉事实，再补充时间覆盖

媒体候选池新增R5_26路径，仍只接受S04/S09A真实视觉证据。先保留Chapter锚点对应的实际帧，再让每个不同Episode有机会贡献代表帧，余下名额按具体主体、稀有语义、直接视觉事实、质量和画面多样性补足。避免普通墙面、人行道占去明显更有代表性的地标、作品、商品或动物图片的机会。

每个Chapter最多8张备选，全日最多40张。只有独立真实图片审查通过、再经有证据绑定的最终选图才允许发表。没有按悉尼或歌剧院做专门的关键词if分支。旧版小V05和V04输入仍保留旧媒体合同。

### 模型调用预算

完整V05长日程安全熔断从历史96次提升至有限180次，V04及小V05仍为96次，同时保留用户原始MP4绝不上云、严格图片身份证据门禁及调用费用审计。此前10秒组冷启动在96次预算触发本地熔断，无法完成S09及后续发布，因此需要真实的阶段预算而不是不受限地重复调用。

## 已验证

- 合成合同测试：非连续同主题Episode可以融合一章，事实只归属一次；错误区间、非法引用与无视觉证据优先锚点被拒绝；图片候选不再由固定等分位置淘汰真正重要的源帧。
- 真实0秒组：S07T/U/V/S09前候选模块运行，歌剧院来源000013的真实帧已被保留在候选池。
- 真实80秒组：首尾歌剧院观察由S07U/S07V/S07W合并到同一主题Chapter，候选池包含000021等清楚地标照片。
- 测试中的小样本仍走历史逻辑，无需整组Episode规划；V04的96调用预算仍保留。

## 尚须最终验收

真实0秒/80秒的预检只是主题规划和候选入池，并非完整用户可见Chapter。下游S09A需逐帧审图，S09B选真实封面/图库，S12作独立图文验证，S14完成遗漏恢复；只有最终发布并通过独立覆盖评价才算有效改进。

目前仍存在若干语义主题组合不理想的候选（例如海事与邻近市区过度合并），不能因为5章合同有效或40张候选齐全就声称达到人工最佳。上线前必须跨12组评测实际可见主题、错章图片、标题是否有图、费用、失败阶段和重复地点的融合能力。
