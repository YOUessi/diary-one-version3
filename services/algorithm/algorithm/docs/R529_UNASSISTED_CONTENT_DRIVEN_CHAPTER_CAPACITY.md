# R5_29：内容决定 Chapter 数量｜禁止外部评测证据泄漏

日期：2026-11-04。实验分支：feature/2026-10-30-chapter-v2-boundary。

## 评测隔离（关键）

用户提供的路线图和任何人工确认的原视频内容边界属于**ChatGPT 外部独立测评的参考真值**，不得直接输入到云端 Chapter 生成器。云端仅使用标准 App Library Bundle、真实抽帧、S04 视觉事实和普适编辑算法，自主理解经历、切分Episode、融合Chapter、选图与写作。即使源视频中本来出现地图画面，也只能由模型从原始帧和事实中自行识别，不能从用户提供的评测参考中获得地名列表、路线标签或人工边界。

本轮曾产生过附加外部评测信息的临时实验输入和模型调用记录，已隔离在 Mac 本地 evidence/work_logs，**不属于无辅助独立云端效果**，不得与正式基线混报；不包含在代码分支的生产输入协议中。对这些临时实验的Chapter数、地标覆盖、片头排除效果不能作为独立能力成绩。

## 生成算法的通用改变

1. 长时V05云端生成允许1–8章，**8是资源安全上限不是目标**。短且连续的单一活动可形成一章；不同且图像事实充分支持的经历可产生6、7或8章。保持基于Episode真实事实的归属，不能简单按视频时长、风景切换或景点名称凑章。
2. S07中的完整Episode归属是硬门禁。模型超出容量时必须**融合有共同实际体验的已有Chapter**；绝不简单删除真实Episode或将无关市集、花园、展览强行拼成一章。
3. 新增只允许已有分组之间合并的有约束修复输入；所有原Episode及其F证据归属保持完整，模型只能建议原章索引的合并，不能创造新图像事实。无足够融合证据则安全拒绝，而不是伪造合并结果。
4. 长时V05可见预览合同允许最多8章；每章的图库仍有5张上限；最多8章时S09候选图像总上限随有效Chapter数量增加。正常短时/旧版路径仍保留历史兼容。
5. Chapter编辑阶段增加“每个新章是否真正拥有独立记忆价值”的条件。相同主题跨时间允许合并，时间和地名本身都不是硬拆分依据。
6. 旧版生产导出合同 production_pipeline_v1.outputs.schema.json 仍限制最多5章，本次**没有对外宣称生产版已支持8章**。超过5章的正式导出需要单独的版本化迁移及客户端联调；当前仅为实验生成与预览能力。

## 实际验证结果与限制

- 通过新测例验证：六个有独立实际证据的Episode可以产生6章，单一连续活动仍可保留1章。
- 测试了超额章节/事实归属后的合并安全边界，丢Episode与跨章锚点必须被阻断，不得自动补造事实。
- 1309个自动化测试通过、25个跳过（当前代码）；测试通过只是合同正确，不代表生成效果已经达成人工编辑水准。
- 下一次真正公平的评测要用**不含外部路线图及用户边界的原始输入Bundle**新生成最终result.json，再由ChatGPT看到实际发布的主图、全部高光、正文与额外测评参考之后独立打分。
- 不上传原始视频和JPG、API密钥或私人调用收据，不擅自合并生产main。

## 后续验收指标

重点比较1) 实际有效的不同活动是否都在最终Chapter中保留，2) 主题是否自然融合但非混杂，3) 同一地标再次出现是否无需强制新开章，4) Chapter数量是否依内容变化而非填满技术上限，5) 最终封面和组图是否支持标题主体，6) 原本无法处置素材的S14是否完整，7) 不会把原视频推广或开场内容当作用户生活事件。

上述质量判断必须来自生成之后的**外部**ChatGPT LLM-as-a-Judge，而不是给云端输入人工路线或再部署内部评分模型。
