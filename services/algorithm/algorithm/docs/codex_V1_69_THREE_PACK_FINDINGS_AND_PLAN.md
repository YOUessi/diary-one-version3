# codex V1.69｜三包全链结果、共性问题与下一步方案

日期：2026-09-07。状态：**约定的三包各一次全新研究链完成；内容质量未接受；下面的修改建议尚未实施。**

## 1. 核心结论

这次终于能把“技术没接通”与“内容选择不够好”分开：S07 Plus＋短编号实际工作，三包都交付了 Chapter 和 Aha，未知短编号为零。但这不等于产品质量修复。

**当前最主要的瓶颈，不是卡片不够多，也不是 API 成本，而是：算法尚未稳定地选出用户真正想记住的经历，并让素材、Aha 和文案围绕这些经历保持一致。**

三包合计 11 个 Chapter、9 个 Aha。已证实有跨卡事实错配、视觉错误传播、同故事重述；也有候选遗漏、精选偏向静态地标而丢掉动作/陪伴、Aha 排序代理指标缺乏区分度。9 条 Aha 全部超过 24 字容忍线，且常把可识别细节写成清单。

不建议马上大改全链，也不建议继续围绕某一个词做多轮重写实验。建议优先处理“选什么、为什么值得记住、Chapter/Aha 如何分工”，并把 Writer 的对象绑定作为独立工程缺陷安排修复。

1. **分组已有正向证据。** 包2夜间餐车/小吃独立成章，室内火锅未混入；室内两件不足成章，但夹肉画面成为 Aha。说明不必降低三件底线或强塞素材，也能保留零散发现。

3. **基本容错保住了素材和卡片。** 全部 102 个素材都保留观察终态与事实，非关键字段失败没有大面积砍素材。跨卡引用检查确实阻止了错绑文案直接展示。
4. **视频和照片可以走同一条研究链。** 三包都是原素材重新处理，账本可追到具体帧；本轮未出现整批无结果。

## 4. 共性问题：真实证据、原因和建议

### P1｜有画面、有事实，却没形成可比较的经历方案

**真实证据：** 包3的 23–25 是夜间历史建筑、街头人群和两人靠近的场景；其中 23、25 没进 Chapter 候选，24 只进 Aha 后落选。41/42 的灯笼街巷也没进文化章候选。最后精选阶段拿不到这些图，自然无法替换相似素材。

**判定边界：** 这是已证实的候选遗漏。它们是否必须另成第五章、是否比已选章更重要，仍是评价问题；不能把“没选中”全部算错，更不能从文件顺序拼出假行程。

**共性原因：** S07 生成少数主题提案后，后续只在这个集合里选择；当前没有充分比较“这一天有哪些具体经历和不同观察侧面”。只用标题、标签或醒目专名很容易变成景物归类。

**建议：** 在现有 S07 任务中，把单位明确为“有内容支撑的经历或探索主线”，让模型比较可行的分组/取舍，并核看未覆盖素材中是否还有遗漏经历。程序不再用宽泛标签自行补组；不要求每张都进组，不新增每阶段反复复核的调用。

**验收例：** 对包3的夜间街头组，既可以有据地并入一个清楚的漫步章，也可以提出独立候选供整日比较；不能仅仅因为还没识别到专名就被排除。最终仍保持 3–4 章的质量目标，不预定必须五章。

### P2｜“分数高”目前不可靠地等于“值得记住”

**真实证据：** 包3办公楼、单车、街头两人等候选的显著性/事实支持/具体性/新颖度多项相同，最终画质 0.88、0.85、0.80 拉开排名。包1“具体性、支持度、新颖度”同样大面积满分；但其中小狗 Aha 与章重复，另一个动物只在画面边缘少量出现。

**可核对机制：** 合法事件代码可取得具体性满分；DISCOVERY 也在其中。新颖度主要是 motifs/主体在候选列表的稀少程度；显著性只有 HIGH/MEDIUM 两档。排序逐字段比较，不是经用户标签校准的兴趣模型。

**建议：** 将合法性与内容价值分开；合法代码、清晰画面、稀少物件只说明“可用”，不自动说明“有趣”。在现有结构模型调用中比较候选具体的可感知价值与相对优先级，减少含义重复的代理分，程序只执行可追查的选择、限额和底线。

**验收例：** 单车可因为真实而特别的构图、互动或个人意义入选；不能只凭“单车在这个包里只出现一次”赢过其他经历。反过来也不写死“有人一定优于建筑”。真实用户两两选择，比又加几个未经验证的兴趣分更有意义。

### P3｜Chapter 和 Aha 相关时，分工仍不稳定

**真实证据：** 包1 C3 小狗同行与 A2 林间小狗明确重述同一故事，这对关系缺失后以 UNRESOLVED 放行。包3 C3 山顶与 A3 金殿的自由说明声称互补，但正式关系未填；Writer 又把 Aha 的金殿细节写进章草稿。

**反向证据：** 包2鹿同故事关系填写完整时，原机制正确工作。不能因此把所有未确定都默认封杀，也不能禁止同时间线、同建筑的独立小发现。

**建议：** 在一次编辑方案中清楚比较相关的 Chapter/Aha 各讲什么，让 S09 选择、S10 精选和 Writer 消费同一分工。针对“有关联的卡片”检查职责是否明确，不做所有卡片两两语义审判、不新增大批拦截规则。

**验收例：** 包1不能同时发布两个同一小狗行走的故事；包3金殿近景则交由用户判断：是否真有独立细节发现，还是章的补充近景。这个边界不能由我替用户冻结。

### P4｜精选可能保住漂亮画面，却丢掉经历本身

**真实证据：** 包3足球候选含比赛与射门，最终全换成比分、奖杯、纸屑；山顶候选中的夜间三人互动被 S10 以氛围不一致省略。包2驾车的两段公路/中控画面重复较高，但模型用不同角色名解释其独特性。包3文化章的两张图实际来自同一街角。

**另一个已证实的输入限制：** S10 再看视频时，当前只取每段的第一个证据帧。包3射门后续动作、包2乘客微笑都不在它实际看到的那一帧里，判断依赖上游描述。

**建议：** 精选围绕该经历的核心内容，比较每件素材真正增加了什么；对视频利用已有证据中更能代表动作/变化的帧，不新增原视频上传或反复补帧。允许实际有新增价值时选 4–5 件，不把三件最低数变成永远优先三件的习惯。

**验收例：** 选三张庆祝还是加入比赛动作，选山顶风景还是加夜间同伴，应能看懂取舍依据。不要自动要求所有体育章必须有射门，也不要直接删掉相近三件导致整章消失。

### P5｜多卡片单次 Writer 仍会混用对象与事实

**真实证据：** 包2夜市章和驾车章被 Writer 交换编号与内容；包3山顶章引用了金殿 Aha 的事实。三次都被正确检查拦住，但转成三个“生活片段＋完整事实”兜底章，体验明显退化。

**建议：** 单独研究简化 Writer 的绑定任务，让程序尽量负责身份与事实归属，模型负责表达。可比较请求内短引用、减小跨卡上下文或按卡隔离等方案；各有取舍，应一次只试一个变量。S07 短编号成功不是 Writer 同样必定成功的证据；按卡隔离也会增加请求次数，不能未经测量直接定版。

保留引用检查、不猜文意交换错稿、不反复调用生成碰运气。是否在用户端展示兜底事实或另种降级状态，属于体验决策，本轮没有改。

### P6｜事实有引用，不等于图像事实真的准确

**真实证据：** 包2骆驼的双峰被写为“两人骑乘”，S04 → S07 → S10 → Writer 一路沿用。已核看标准化图及原图。包3赛事专名与 Honeywell 招牌也出现错读后进入标题。包1文案补写小狗“渐隐于尽头”、包2补写“未开始的拍摄”和将站姿写成蹲姿，现有引用校验不会自动证明这些措辞正确。

**建议：** 先收窄“为记忆表达真正需要的事实”，减少不必要的精确专名、装饰性定语和无依据动作进程；不删除事实账本。已有看图阶段应围绕核心事实工作，避免后续把上游说明反复复述当成独立验证。用这些真实错例做一次局部单变量模型/输入对照，必要时再决定是否更换视觉模型。

不先造猫狗/石板路黑名单，不新增每条事实都多模型裁判的流程。上述真实错误也不能外推为“所有动物都不可信”。

### P7｜文案焦点问题比精确字数更重要

**真实证据：** 九条最终 Aha 的可见字符数为：
包1 40/44/40；包2 46/39/41；包3 40/51/50。全部超过目标 20、容忍 24，现有软标记已记录，未强砍或 API 重写。很多句子同时列举颜色、背景、标牌、器材、物件。

**建议：** 保留软字数约定，不转硬阻断。先选最值得表达的动作或发现，再用必要环境承接；允许适度氛围，不要求所有识别对象都入句。不直接冻结“最多三个 object”这样的示例数字，也不让“颜色不重要”变成一刀切规则。

**验收例：** 夹肉 Aha 的焦点可以是筷子夹起那一口，不必列酸黄瓜、调料碟、台面；但最终取舍和表达要以真实图与用户偏好验证，不把这道菜写成专用模板。

## 5. 我建议的推进顺序

### 下一小步：先做 S07–S10 的“经历选择与分工”方案，不增加新调用

这一小步只交付一份简短任务合同和真实卡片对照：

1. 输入仍是事实与已有证据，保留无可靠时间声明。
2. 明确 Chapter 的经历/探索主线、未覆盖素材中的潜在遗漏。
3. Aha 用可感知的独立价值做相对选择，不把合法事件代码当兴趣满分。
4. 明确相关 Chapter/Aha 的内容分工；精选不丢掉这条主线的关键素材。
5. 用三包中的真实例子解释新旧取舍，不再构造语义反例，不写场景专用规则。

这是**拟议设计**，不是本轮已经实施的新算法。先让用户介入主观边界，再只改一个可归因的环节、冻结候选、跑三包各一次完整链。局部离线检查用于工程诊断，不能代替用户要求的完整验证；也不把新版本的偶然漂亮结果当成稳定质量提升。

### 独立的下一工程修复：Writer 对象绑定

经历分工的输出明确后，再隔离处理 P5；不与换视觉模型、调兴趣分、改长短文案同时混在一个实验里。真实包2/包3错配回执作为回归证据，检查错引用被挡住以及正确绑定能够发布。方案需要新的真实返回验证，不用离线旧输出冒充新模型质量。

### 随后才处理视觉事实与文案输入

针对 P6/P7 在真实案例上验证“减少无关细节、保住核心事实”的输入/任务设计；若仍不可靠，再评估模型升级。不能把此阶段变成某一张图措辞的无休止打磨。每轮到预定停止点就汇报，统一看最终卡片是否更好。

### 当前只需要用户介入的三类体验边界

- **章的粒度：** 白马寺与洛阳夜街能否共享“文化探索”主线，还是应优先分开；不要同时重问最低三件、目标三四章等已定原则。
- **精选取舍：** 在比分、领奖、比赛动作都有的情况下，用户更希望章保留何种经历代表性；不预先写死赛事模板。
- **Aha 独立性与价值：** 金殿近景相对山顶章是否有新增故事；普通单车/办公楼需要什么真实理由才值得单列。

这些判断可以直接在真实卡片上集中打分/选择后归纳共性。无需对每个字段逐条回答“同意”。

## 6. 如何积累真实数据与验证，而不是在三包上越调越像

这三包已经多次用于开发，是**回归素材**，不是新的未见用户测试集。当前不能承诺泛化效果或用户满意度。

建议先收集真实评价数据，不急于用三个包微调模型：

| 评价层级 | 应标什么 | 本次真实例子 |
|---|---|---|
| 原素材/证据帧 | 主要事实是否正确；关键动作在第几帧；不确定处 | 双峰是否被错写为骑乘；视频笑脸是否只在后帧 |
| 经历分组 | 哪些素材有共同经历；哪些只是类别相似；是否漏掉主线 | 山顶图48与山顶组；夜间街头23–25 |
| 精选集合 | 删哪一件、换哪一件、原因；不是只给整章总分 | 相近公路图；同街角两张夜景 |
| Chapter/Aha 配对 | 同故事重述/独立发现/暂无法判断 | 小狗同行；山顶与金殿 |
| 文案句子 | 不准确片段、焦点冗余、喜欢的氛围；关联到具体素材 | “两人骑乘”“未开始”“扫码器与标签” |
| 整日结果 | 最想留下什么、遗漏什么、愿不愿保留这套结果 | 观赛、夜间同伴、街头漫步是否被表达 |

标注必须关联运行版本、输入摘要、卡片 ID、素材 ID 和帧；保留原结果，不把人工修改直接写回原模型记录。算法侧审阅与素材拥有者评分分开保存。

后续评测按**用户/天/原视频来源**划分开发集与保留集，同段视频的抽帧不跨集合；避免看过同一人同一天后声称是新用户检验。纳入通勤、居家、亲友、旅游、运动、稀疏素材、低光/模糊素材，不按本报告的案例构造错误语句。

比较版本时匿名、尽量不透露哪个是新版；既看接受率/偏好，也看错误事实、错聚、同故事重复、关键经历遗漏、实际修改负担和延迟/费用。指标分别报告，少量用户下不宣称统计稳定。评价分歧本身也是兴趣差异的数据，不由单一审阅者强行变成通用规则。

只有在积累足够、分布更广且有一致标注的问题后，再决定是调任务输入、换模型、训练排序器还是微调。训练后的验收仍留给未见用户/天，不能只测训练例子。
