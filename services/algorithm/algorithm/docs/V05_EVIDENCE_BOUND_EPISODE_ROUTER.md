# V05 长时日记的证据绑定 Chapter 规划

## 痛点

旧版在 S07/S08/S09B 要求模型一次性手写、反复修改数百条 fact_ids。大模型能识别不同体验，但常把几百条事实挤进一个笼统主题，或生成零事实的自然园林章。S09B 同时改章节、改归属、做图片选择；最终门禁丢掉所有无效条目。此前 V04.1 96 次调用限制错误计入已复用的 S04 真实图像结果，使最终验证过早中断。

## 新流程

1. S04 识别和 S09A 逐帧图像审核继续采用真实图片，不能上传原始 MP4。
2. S07X_PRODUCT_EPISODE_ROUTE 依据每段源视频的视觉观察，只输出闭区间 start_index/end_index、theme、experience_kind、reason。模型不需要手写任何 fact_ids 或图片 ID。
3. 若最大章过长，或五章里存在极短尾章，S07Y_PRODUCT_EPISODE_REVIEW 单独审查；不是必须拆开，也不是强制五章，同质骑行可仍是一章。
4. 代码检查区间严格覆盖整个导入序列，按来源视频自动将每条已核验事实归属唯一 Chapter，拒绝零事实章、重复资产与未知 ID。
5. 均衡提供每章已核验事实对应的图片候选。独立图像模型对每张候选图审核具体可见内容与源事实是否匹配。
6. S09B_PRODUCT_EPISODE_MEDIA_ONLY 只可选择每章的 hero 与图库，不可再更改章节的主题、边界或事实归属。组图理由使用先前独立审核通过的精确画面描述。
7. 后续事实/文案核验、图片关系检查和正式发布门禁不绕过。未核验状态须可追踪，不可冒充内容本身不重要。

## 通用性、安全与验收

- 任何真实地点、数据集名称与具体章节数量都不写入算法；按可核验的主题、活动、独立经历做决策。
- index 是导入顺序，不证明实际行程、同伴、返程、时钟或因果关系。
- 长期同一活动可以合一章；多种完整独立经历不能仅因相同 WALKING 标签压为一章。
- 本地合成测试检验区间覆盖、事实唯一归属、空事实拒绝、跨章媒体引用和零真实调用的 S04 复用计数；不替代图像效果验收。
- 完整真实回归要求检查最终可见 Chapter、代表图片、自然语言文本、覆盖、人工编辑主题相似性、失败恢复及调用成本。只有中间规划达到五章而最终没有发布，判为失败。
- 真实图片和临时 stage API receipts 保留在 Mac 的本地实验目录，不进入 Git 仓库。
