## 2. V1.75 修改解决什么

V1.74.1 的真实 S09 收到 35 条事实，但需要自己在扁平事实列表与 4 个 Chapter 间做交叉比对。一个未进入 Chapter、具有完整现场和人员操作的事实被无声漏过；模型却选择了三项随后被关系矩阵判定重复的内容。

V1.75 只修这个结构问题：

- 给每条事实明确 Chapter membership；
- 强制逐条审查所有未覆盖事实；
- 要求说明事实支持的 revisit hook；
- 把 selected Ahas 定义成已能共存的最终集合；
- 强制完整逐对关系数量，缺失 fail closed。

它没有证明模型一定会选出好 Aha；必须由新的真实完整链验证。

## 3. 当前主要风险

### P0：Aha 真实质量未知

需要验证模型是否真的逐条审查未覆盖事实、是否能从事实中抓住体验核心、是否会继续输出自相矛盾的最终集合。

### P0：Web 与研究候选版本不一致

不得把本地 V1.75 完成误写成用户测试页已升级。接入前要核对 Web health、结果 schema、policy handshake 和 media-only Chapter 的 UI 合同。

### P1：无可靠时间/GPS

当前手机测试素材多为 sequence-only。聚类不能使用真实停留时长、地点移动或拍摄时间；这会限制连续故事和同地不同阶段的判断。算法必须保留“不知道”，不能从导入顺序编造时间。

### P1：S04 事实/OCR 仍可能不稳定

已有一次英文事实输出和一处可疑 OCR。当前正确方向是积累真实错误率和类别，而不是为某个牌坊文字增加词表。

### P1：Chapter 第四章可能仍偏“地标/标识集合”

需要用户逐章评价主线是否像一次经历，而不是仅凭标签或地点名称合并。

### P1：高强度容量未验证

当前真实包 1 为 20 视频/74 帧/35 facts；产品高强度日可达约 186 素材。需要测上下文体积、S04 批次数、总 attempt、时延和成本，不能凭小包推断。

### P2：海外文案合同未完成

当前中文测试使用字符目标；英文及其他语言不能机械复用 20/24 中文字符，需要单独定义 word/content-word、展示宽度、可访问性和 locale eval set。

## 4. 接手后的建议顺序

### Step 1｜V1.75 素材包 1 全新完整链

- 从原视频重新标准化；
- 完整跑 S04–S12；
- 不复用旧视觉回复；
- 不单独重放 S09；
- 记录逐阶段时间、Token、价格和输出。

### Step 2｜逐卡人工复盘

每条建议绑定到具体对象：

- Chapter ID；
- 具体素材/帧；
- 分组是否合理；
- 选材重复度；
- 标题/正文问题；
- Aha 是否有独立回看价值；
- 具体修改建议及归属阶段。

不要只给“整体 6 分”或“感觉一般”。

### Step 3｜只归纳跨样本共性

先收集问题，不立即为每个问题加规则。至少在多个真实样本重复出现、且能定位到同一结构原因时，才提出运行时修改。

### Step 4｜再决定素材包 2/3

若素材包 1 暴露结构性阻断，先停；若目标机制有效但存在普通质量波动，再保持同一冻结候选跑包 2/3。

### Step 5｜质量稳定后再接 Web

接入需要独立检查点：输入 bundle、policy handshake、结果 schema、失败状态、media-only Chapter UI、版本回滚和用户评分回传。不要在算法验证过程中顺手改 Web 默认。

### Step 6｜最后处理 Production

包括队列、存储、权限、幂等、发布原子性、S13 HQ、监控、限流、隐私与保留策略。当前仓库只有 Production-shaped reference，不能当线上实现。

## 5. 真实评价建议字段

每次测试至少保存：

- run/candidate/model/version；
- 输入资产、Evidence 和时间可信等级；
- 每阶段调用、Token、费用、耗时；
- 每个 Chapter 的主线、成员、3–5 个精选素材和重复项；
- 每个 Aha 的事实、代表帧、revisit hook、关系与文案；
- 每个被拒项的明确原因；
- 用户逐卡评分与自由反馈；
- “算法错误 / 模型波动 / 输入不足 / UI 表达 / 尚不确定”分类。

这些数据以后可用于阈值、Prompt、模型选择和监督数据建设。现在不应在只有三包数据时宣称“训练完成”。
