# 05｜已冻结原则与禁止事项

以下是接手后必须继续尊重的产品/算法边界。新的真实证据可以形成新版本，但不能静默改写这些历史决定。

## A. 产品输出

- 全天 Chapter 常规目标 3–4 个，内容丰富时允许第 5 个；不是机械配额。
- 每个 Chapter 3–5 个精选素材；去重应改善卡片，不得因过度去重轻易删除整个合格 Chapter。
- Aha 允许 0–3 个；有充分事实时主动寻找 2–3 个，稀少日也要认真寻找小精彩，但不能强行填充。
- Chapter 文案 1–2 句，有具体画面和适度氛围；事实/标签承担检索，不要求文案罗列所有 objects。
- Aha 中文 20 个可见字符为目标、24 为硬上限；不反复调用 API 重写。

## B. Chapter 与 Aha 的关系

- 时间线重叠不等于故事重复。
- Aha 可嵌在 Chapter 时间段中，但必须有不同回忆职责；Chapter 的核心高潮不应重复拆成 Aha。
- 同主题可有多个 Chapter/Aha，只要是不同经历、不同体验核心并有证据。
- `SAME_STORY` / `UNRESOLVED` fail closed；缺失关系不能默认独立。
- 程序不在模型拒绝后从候选池自动补位。

## C. 事实、聚类和相似度

- 不能只用同对象词做聚类；需要整体经历、活动、环境和连续性证据。
- 相似 Manual 可从 Chapter/Aha 候选中抑制，因为 App 有独立 Manual 窗口；但素材和事实账本必须保留。
- 长 Chapter 可以保留时间上相隔较远、具有不同构图/内容贡献的相似外观素材；不能把“都是古建筑”机械去重。
- 没有可靠时间/GPS 时只使用 sequence，不编造真实时间线。

## D. 工程与模型调用

- 每次正式质量测试跑完整相关流程，不用单阶段重放冒充 end-to-end 结果。
- 不通过反复 API 调用“抽卡”获得合格 Writer 文案。
- S09 一次、Writer 一次；V1.75 不增加模型阶段。
- Writer 失败不发布原始事实或通用套话；Chapter 内部结构/媒体可保留，Aha 关闭。
- 任何 Provider、Token、费用和时间必须按阶段记录，不能只给总数。

## E. 规则设计方法

- 用户举“小狗活泼”“古镇石板路”等例子，是为了说明共性体验问题，不等于授权写入猫狗、古镇、颜色或物体词规则。
- 不在没有真实图片错误的情况下人为构造语义反例并沉淀大量 gate。
- 协议 fixture 可以验证编号、状态、关系闭合与 fail-closed；不能声称验证了视觉/语义质量。
- 新问题先积累真实证据、定位责任阶段、归纳共性，再修改。
- 随时从全链路检查局部工作是否仍服务最终用户价值，避免长期钻入低价值细节。

## F. 数据与权限

- 三套测试素材已对原项目开放用于算法测试，但本交付包不复制它们；新接手者仍需由项目 Owner 提供受控访问。
- 真实素材/标准化帧/派生事实发往外部模型前，必须确认目的地和授权。
- API Key 不进入源码、日志、交付包或公开 Git。
- 当前允许修改的范围是算法仓库；Firmware/SDK、正式 App、共享状态、Web 默认和公开部署需要独立授权。

## G. 版本与声明

- 冻结 candidate runtime 不覆盖；发现问题时创建 superseding checkpoint。
- 代码完成、本地测试、真实模型执行、内容质量、Web 生效和 Production readiness 是六个不同状态。
- 当前 V1.75 只到“代码与本地测试完成”；真实质量、Web、Production 均未完成。
