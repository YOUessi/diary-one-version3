# Diary One Chapter V2：跨场景泛化评估与反过拟合协议

版本：2026-10-30 · 新分支 feature/2026-10-30-chapter-v2-boundary。

**总目标：让算法按可见经历的语义、时间、主体和证据决定 Chapter/Moment，而不是把悉尼第一组人工5章答案写进程序。**

## 1. 场景无关的基本定义

- **Asset**：一次10秒设备录制，可能包含多个不同时刻的画面；设备间的连续性不能从导入顺序推断。
- **Frame**：Asset中的静态选中图，附相对源片PTS和唯一frame_id。
- **Scenelet**：短小场景/事件单元，可以来自同一或数个有据可查的Asset；不等于Chapter。
- **Chapter**：有独立回顾意义的主题或经历，可包含多个Scenelet。
- **Moment**：有具体价值、可单独回看，但未达到独立Chapter范围的细节或事件。
- **Abstain/Pending Review**：证据不足时允许不命名、不独立拆章、等更多图像确认。

**Chapter个数是内容生成结果，不是目标标签**：目标产品通常展示当天3–5章，但重复的一天可能只有1章；丰富一天也不能凭视觉变化数量直接拆成许多章。

## 2. 六类固定用户画像与正反例

| 画像 | 需要发现的错误（过合并） | 必须避免的错误（过拆分） | 独立评测素材 |
| --- | --- | --- | --- |
| 1 无脚本日常 | 不同具体活动在泛泛“日常”章中消失 | 不同路口、同一工作场景每拍一次就新增Chapter | 待补真实长序列、跨室内外 |
| 2 旅行 / Citywalk | 不同参观、市场、海港和园林经历被城市标签吞并 | 同一地标多个角度或街角变化硬拆章节 | 悉尼221帧 + 其他独立城市保留测试 |
| 3 亲子家庭 | 游乐、做手工、用餐等清楚不同经历遗漏 | 同一游乐设施不同动作/角度硬拆；不可推测亲属关系 | playground_kids / stroller_walk；长序列还不完整 |
| 4 双手忙碌兴趣 | 做饭与手工等不同任务被泛化为“在家” | 切菜、洗菜、翻炒、摆盘自动拆成4个Chapter | 目前正式合格素材不足，需要扩充 |
| 5 轻运动户外 | 骑行与有独立证据的停留/发现被忽略 | 桥、绿道、土路每次环境变化都拆成章节 | rural_cycling / nagoya_cycling |
| 6 钓鱼 | 明确鱼获、准备、更换钓点等高价值事件丢失 | 同钓点重复抛竿、等鱼硬拆成多章 | river_fly_fishing / kayak_bass_fishing |

这些是**测试用例和反例**，不是固定产品规则。实际情况由有效图片、可信时间与独立人类评审判定。

## 3. 第一级：通用代码合约测试（已经完成）

- **所有6个领域**：若S07关键事实被S08全部丢弃，检测为待核验资产，而非自动保留该章。
- **所有6个领域**：同一经历的两份草稿若合并且全部事实有去向，不会仅因章数减少就重新触发图像请求。
- **所有6个领域**：若某草稿事实已转成独立Moment，则不是“未出现”；若Moment只覆盖一部分，仍审核剩余丢失事实。
- **变形测试（Metamorphic）**：只改主题文案、语言、Chapter编号而不改事实引用，异常识别结果应保持。
- **负例**：陌生fact_id、重复帧、非法结构不能创建图像证据或强制新增Chapter。
- 这一层只证明数据合同，**不能证明LLM对6类视频的语义判断正确**。

## 4. 第二级：真实视频冻结对照（待执行）

**同一模型、同一Prompt基线、同一组素材**，消融改动只在算法架构；不能将换强模型和结构升级混合计算效果。

冻结如下4个算法版本：
- **A0**：R5_21旧流程（原始S07/S08/S09B）。
- **A1**：P0锚点重新核验 + 合并/删除去向合同。
- **A2**：A1 + Scenelet全局时序图 + 基于独立事件的边界优化。
- **A3**：A2 + 逐章媒体召回与全局时间/视觉覆盖验收。

每个版本对6类用户案例都要报告完整案例级数据，而不是只写一个总正确率：
- 高价值真实事件有多少被Chapter、Moment或Aha记录，多少毫无说明地消失；
- 同一经历被过拆成几个Chapter，独立经历被合并的比例；
- Chapter主题与每张媒体是否匹配（正文覆盖与图片覆盖单独报告）；
- 短时内容（前1秒/后1秒）、暗光、视角不完整、字幕干扰；
- 时间依据、跨片假连续性、未经证实的身份/地名/动作断言；
- Chapter数量分布与自然性（不能只看是否等于5）；
- 平均/尾延迟、调用次数、输入/输出Token及真实账单差价；
- 不同种子、不同题材和重复样本的稳定性。

人工至少双人独立盲审，对有争议边界再仲裁。人工写的悉尼5章只能是**开发参考**，不能同时作为最终独立测试标注。应按视频源、题材和事件主体切开训练（如有）/开发/留出集合，避免同一天连续画面泄漏。

**现阶段不能说六类均已具备足够真实长序列用于完整Chapter独立验收。** 做饭/手工等双手忙碌兴趣、普通无脚本日常、购物社交与亲子长序列需要另外补齐。短片文件夹中的重复采样或同源素材不能被当成独立实验样本。

## 6. 明令禁止的场景特判

不要在算法中：
- 对 `CITYWALK` 专门提高Chapter数，对 `FISHING` 专门压低章数；
- 把“悉尼、植物园、歌剧院、集市、教堂”作为必须保留/拆分的关键词；
- 把1天最长、景点最多的测试默认定为5章正确；
- 基于旧S07草稿的事实缺失直接要求强制发布被删章；
- 允许没有真实照片证据的Chapter以美观文案或同类活动标签获得支持。

允许类别作为**理解不同生活事件及风格的条件**，但不允许类别成为可以绕过证据的硬性章节数量/合并规则。

## 7. 提交与验收门禁

- P0每次修改后必须运行全量Python测试，保留独立骑行fixture；
- P0更新应至少有一组跨六类的合成反例测试，且有一组合法合并负例；
- 做真实A/B时不得只展示悉尼或只展示提升样本，必须报告全部六类的原始差异；
- 尚未完成真实多场景盲评时，只可宣称“代码数据流修复/回归通过”，不得宣称“Chapter已普遍改善”。
