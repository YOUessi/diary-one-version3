# Chapter V2 · P0 — S07 草稿章节核心视觉证据保留

日期：2026-10-30。独立研究分支 feature/2026-10-30-chapter-v2-boundary，基于已推送的 R5_22 fe0415c。

## 实际原因

悉尼第一组包含161个10秒片段、221张MobileCLIP S0 FP16 v07图。S07最初提出4章：海港、达令港、教堂、植物园。S08将达令港事实并入海港，把原C03教堂改为新C02，并丢掉原C04植物园的10条章节事实。

旧逻辑随后只从S08幸存章节的资产中挑选视觉核验目标：被删的植物园连证明自己应该保留的看图机会都没有。因此P0优先修这个数据流失，而不是直接改Prompt、改模型或固定输出5章。

## 已经实现的代码

- 新增 chapter_transition.py：从S07的合法focus_fact_ids抽取来源于不同10秒片段的视觉锚点；对S07→S08按事实交集审计真实去向，检测章节合并、遗漏和Chapter ID复用。
- 只有焦点事实在S08后真正消失时才补充看图核验。已合法合并并保留全部焦点事实的章节（例如同一路程的多段骑行）不额外触发候选，避免影响现有推荐顺序。
- 经过看图核验的丢失焦点被保留为S09B媒体候选，供模型重新判断该主题是否独立存在；无图像证据不予恢复。
- S09B仅在存在丢失焦点时获得精简审核摘要，避免给所有正常会话都增加大量Token。
- decision_trace新增草稿章节去向、视觉核验后的映射、最终映射和补充媒体候选的审计记录；EDIT_REVISION更新为R5_23 P0。
- 增加test_chapter_transition.py，检验候选独立性、拒绝外来事实、场景合并兼容、只保留确实丢失的锚点等。

## 悉尼真实数据的离线核对

使用原R5_21结果、Bundle和Observation重建catalog，得到161个Asset及212条初始事实。新审计准确定位：
C01海港→C01；C02达令港→C01；C03教堂→C02；C04植物园→无对应章节。

其中真正丢失、需要额外看图核验的C04核心锚点为F193、F202，源Asset为V143、V151。模型是否应该把植物园恢复为独立章，必须在这两组图片核验后决定，不能把草稿主题当成真值。

## 重要边界

目前是第一批P0代码：恢复“丢失主题获得视觉核验和候选展示”的机会，不是已经实现了最终自动分章修复。没有新一轮付费API运行，不能声称悉尼已从2章提高到5章。

尚需P0第二批：显式的合并/删除证据合同和结构重规划门禁。后续P1再引入全局Scenelet、可信时间线和可配置章数，P2再优化逐章媒体选择与实况Chapter。老R5_22工作区、生产部署、原视频和端侧模型未修改。
