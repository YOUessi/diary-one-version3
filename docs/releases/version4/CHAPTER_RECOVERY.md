# R5_19 Chapter 传输与断点恢复

2026-10-23，基于 Build 5 源码 5f238f5；分支 `fix/version4-chapter-recovery`。本页记录本地实现和验证，不代表公网已升级。手机 S0 FP16 v07、App、Chapter/Aha 文案和选图审核要求未更换。

## 修复行为

- S04 视觉批次及产品编辑器调用（包括 S09）统一识别超时、TLS EOF、连接重置、响应正文中断与 HTTP 5xx。一次传输失败最多追加一次重试，遵守已有全流程预算。等待使用指数退避函数与抖动；当前一次追加重试的等待约为 0.5～0.75 秒。证书、401/403、429及未知错误不自动重试。
- 成功的视觉批次先保存检查点，后续章节生成失败不丢失这些观测。恢复时重新验证检查点中的事实和引用，复用成功批次，仅重新请求失败或无效的视觉批次；后续章节生成和内容审核重新执行。
- 输入仍有 FAILED 或 unresolved 时，算法保留 PIPELINE_BLOCKED。BFF 独立检查 unresolved、FAILED 和覆盖状态，不能因为已有 Chapter 或声称 READY/COMPLETE 就发布不完整结果。PARTIAL 中通过校验的事实仍可使用；有效的空结果仍允许返回。
- 原始 FAILED 且无可用事实保持失败，不能转换成“没有值得记录的内容”并缓存。已保存但重新验证失败的检查点按未命中处理。
- 失败尝试有审计记录；恢复运行标记 RESUMED_PERCEPTION_CHECKPOINT，包括恢复后再次失败的情况。复用结果不重复计入当前模型调用数、token及费用估算；原调用来源保留。网络失败的实际供应商用量可能未知，估算不是账单。

## 启用方式

产品 HTTP 入口在 `DIARY_ONE_X02_EDITOR=product_v1` 下自动使用：

```text
<x02_run_audit_dir>/perception_checkpoints/
```

该目录须在服务重启后保留、由服务用户读写。重试发送原 manifest 和相同图片字节即可；临时上传目录变化不影响复用。BFF 和算法服务需要部署匹配的本次修复，现有手机包不需要为这些后端修复重新打包。

直接调用算法的实验脚本必须显式传入检查点目录：

```python
result = run_x02_product(
    manifest_path,
    gateway,
    checkpoint_dir=experiment_root / "perception_checkpoints",
)
```

省略该参数保持全新运行；HTTP 旧研究入口不启用检查点。当前 Downloads 中已经启动的 R5_18 实验脚本没有被修改，也没有自动接入本修复。

## 复用边界

检查点绑定完整 manifest、实际图片字节、provider/model、接入地址摘要、请求选项、提示词、结构定义和算法包源码。标准生产网关提供模型与请求选项；自定义网关也必须公开这些配置以保证身份准确。任何相关输入改变都重新识别。检查点不跨源码版本沿用，历史 R5_18 中未保存的模型输出不能凭空恢复。

只缓存完整通过校验的视觉批次；混合失败批次不整体缓存，已经成功的独立批次或拆分后的成功子批次可保存。后续阶段无通用结果缓存。检查点损坏、目录不可写均降级为普通运行并记录原因，不绕过内容校验。

目录/文件使用私有权限，原子替换，单条最多8 MiB；不写入图片正文或凭据。检查点含视觉事实，应按服务审计数据管理。旧命名空间目前没有自动清理，运维按数据保留策略清理；删除后只会失去复用能力。校验和用于发现损坏，不替代文件系统访问权限。
