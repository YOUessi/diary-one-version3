# Diary One｜三组全新偏移抽帧：V1 自然叙事与时间合同效果实验

2026-11-11，真实 qwen3.8-flash API 实验。结果来自 Mac 上实际运行的独立模型请求；**未使用人工标注好的 Chapter/图片答案作为模型输入；未上线**。

- 博物馆为 FP16-V07 offset 40s，国家公园为 offset 70s，悉尼为 offset 30s 且整段剔除第一个落在 72 秒片头范围内的采样片段（后续从原视频 150s 开始）。
- 本轮新图片与之前直接测试的博物馆0s、国家公园0s、悉尼80s组 **逐像素 SHA256 均无重合**，全部 API 请求均有新的唯一 request_id。
- 不宣称供应商**文本 Prompt 前缀缓存**彻底关闭：当前 Qwen 请求记录没有独立、可核验的 cached-token 字段；可确定没有复用上一轮的完整图像输入或本地生成结果。

## 四条独立路线（必须区分）

**A = 原始冻结 V1：** 完整原版 Prompt + 新偏移组全日 JPEG，一次 Direct VLM 给故事和 Gallery，原样保留 JSON；严格检查越界/跨章图库。
**B = 原版 V1 + 严格旧图库边界对齐：** 新增一次全日图片调用，只返回 end_clips，**同时必须保留所有原图库和 Key Moments**；冲突则拒绝，不移动/修补图片。
**B2 = 完全冻结 A 的标题/Story 和 Chapter 数量，先对齐边界，再重做每章 Gallery：** 每章只输入本章真实 JPEG；新 Gallery 不保留 A 的旧图，但保持所有故事文字逐字不变。
**C = 保留 V1 的叙事/具体作品原则，单独生成 Title/Story/end_clip 的 Narrative Planner，再依边界逐章看图生成 Gallery：** 与 A 是不同的第一次 VLM 调用；删除 Gallery 指令来避免格式冲突，不无限增加新规则。

这些方法改变的不止模型阶段数，还改变输出任务/字段；它是不同架构的实测，不是严格的单文字变量因果实验。

### 关键因果现象

- 冻结 V1 的主题完整性较好：博物馆 4 章、国家公园 4 章、悉尼 8 章。但它不是稳定交付：悉尼本次出现一条无效 Key Moment 图像索引，同时把 234 张输入中的 160 张选入图库（8章各20图）。
- **保留旧图片再强行补 end_clip 行不通。** 博物馆与国家公园的原 V1 图库在相邻章节间有交叉归属，B 两次都被严格拒绝；悉尼 A 本身索引失效，B 不启动。
- **B2 能在博物馆保持原始叙事。** 4 章原 Story 一字不改，重新按所属 Clip 选择 26 张图，但它并不自动保证选图更精简：近像素重复比原 V1 增多。
- B2 在国家公园、悉尼的 end_clip 生成发生数值越界/不递增：国家公园实际 172 CLIP 却生成末端 192，悉尼实际 160 CLIP 却生成 183 再回到160；程序拒绝，未发布。
- **C 在三组都更细分**：博物馆 4→6，国家公园4→7，悉尼8→12；这是用户所指出的“为了时间边界导致经历碎片化”的独立新素材复现。
- C 的博物馆与悉尼通过时间/图片引用合同；国家公园在第4章 Gallery 的 Key Moments 超过10项，两次重试均失败，整天不能交付。

## 工程方向（这轮不切线上）

保留 **V1 的自然叙事内容原则作为主基线**，但不能直接复用它的全部图库；把叙事、时间归属与图库合同真正分离。当前仅用自由文本生成 end_clip 的对齐步骤明显不可靠，需要可约束的边界候选与单调性验证，而不是在 Prompt 后反复叠加更多时间规则。

新方案下一次公正 A/B 的标准：冻结相同的V1自然 Story，统一图库上限和关键瞬间预算，独立验证具体作品/地标，至少跨三组新的素材复测，并记录严格合同通过率、视觉表现、延迟和 Token。
